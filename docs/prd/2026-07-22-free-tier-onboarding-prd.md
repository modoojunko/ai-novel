## 核心价值观

> **人铸灵魂，AI行笔墨。**
>
> — 创作者赋予故事灵魂、角色、情感和价值观。
> AI 只是执行工具，负责把创作者的意图转化为文字。
> 工具不取代人，人始终是创作的第一主体。

### 这句话对产品设计的影响

| 领域 | 含义 |
|------|------|
| **产品定位** | AI Novel 是"写作工作站"，不是"AI 写作工具" |
| **AI 的角色** | 辅助描写、扩展段落、生成选项，不决定剧情走向 |
| **合规安全** | 人主导创作 → AI 是工具 → 不构成 "AI 生成内容" |
| **对外宣传** | 强调"帮你更好写"，不是"替你写" |
| **功能设计** | AI 输出永远是"建议"而非"定稿"，需要人确认 |
| **定价理由** | 用户买的是写作工作流效率，不是 AI

## 0. 商业模式约束（不可违反的架构红线）

### 合规成本
| 项目 | 费用 | 触发条件 |
|------|------|---------|
| ICP 经营许可证 | ~5-6 万/年 | S端 有收款/交易行为 |
| AI 生成式备案 | ~3-5 万/2年 | 产品自称或被视为"AI 服务" |
| **合计** | **~8-11 万/年** | 违反任意一条即触发 |

### 不可违反的铁律

**🔴 S端 绝对不能有：**
- 收款/支付交易 → 转由淘宝处理
- 代用户调 AI API → 必须用户电脑直连
- 存储用户小说内容 → 全在本地
- 用户实名认证 → 不碰隐私数据
- 订单系统 → 不碰交易信息

**🔴 C端 绝对不能有：**
- 内置共享 API Key → 不属于"用户自配"范畴
- 预填任何团队的 API Key → 会被认定为 AI 服务提供方
- 自称"AI 写作产品" → 对外称"写作工具"，AI 是可选集成能力

### 架构推导
```
S端 有交易 → ICP 认证 → 5-6万/年 → ❌
S端 代调 AI → AI 合规 → 3-5万/2年 → ❌
C端 内置 Key → AI 服务 → 3-5万/2年 → ❌

✅ S端 仅 License 验证 → 无 ICP 风险
✅ C端 用户自配 Key → 非 AI 服务，工具属性
✅ 淘宝承担交易 → 他们有 ICP
✅ AI 提供商（DeepSeek/OpenAI） → 他们承担 AI 合规
```

### 对产品设计的具体约束
| 决策 | 原因 |
|------|------|
| AI 试用 = 软件功能开关，非 API 额度 | 无法赠送 API 调用（S端 不碰 AI） |
| API Key 用户自己配置 | 不属于"AI 服务提供" |
| 激活码通过淘宝卖 | S端 不需要支付能力 |
| 免费层 = 手工写作 | 不涉及 AI |
| 定价信息放淘宝，不放 S端 | S端 不涉及交易信息 |

## 1. Problem Statement

用户从抖音/B站看到宣传 → 到 S端 注册 → 下载 C端 → **然后呢？**

当前流程断层：
1. 首次打开 C端 → 看到登录页 → 点"打开浏览器登录" → S端 授权 → 进入 dashboard
2. 看到"无套餐"→ 点"激活新码" → 需要输入淘宝买的激活码
3. 还没体验产品就要付费 → **大部分用户直接流失**
4. 即使付费了 → 看到 API Key 配置页三个空白输入框 → **非技术用户再次流失**
5. 写完了 → 找不到导出按钮 → 内容困在应用里 → **留存率低**

## 2. Goals & Success Metrics

| Goal | Metric | Current | Target |
|------|--------|---------|--------|
| 提高注册到激活转化 | % 注册用户完成激活 | ~5% (估算) | 20% |
| 降低 API Key 配置放弃率 | % 用户填写 API Key | 极低 | 60% |
| 提高新手首次体验完成度 | % 新用户完成1章写作 | 极低 | 40% |
| 导出使用率 | % 有内容的用户使用导出 | 0% | 50% |

## 3. Non-Goals

- 不做社交/社区功能（P2）
- 不做移动端（P2）
- 不做 epub 导出（P1，先做 .txt/.md）
- 不改剧情推演引擎

## 5. 详细功能规格

### 5.1 免费体验层

**重要说明：AI 试用 = 软件功能使用权，非免费 API 额度**
用户始终要自备 API Key。试用期只是软件端开关，决定是否允许调用用户配置的 Key。
（S端 不碰 AI，无法赠送 API 调用）

**后端改动 (`auth_local/service.py`)**

```python
# 新增常量
FREE_AI_DAYS = 3        # AI 试用天数
FREE_PROJECT_LIMIT = 1   # 免费项目数限制

def check_permission() -> dict:
    """检查当前用户权限（含免费层逻辑）"""
    cfg = get_local_config()
    tier = cfg.get("tier", "none")
    expires_at = cfg.get("expires_at", "")
    created_at = cfg.get("created_at", "")
    
    if os.environ.get("DEV_MODE"):
        return {"allowed": True, "tier": "lifetime"}
    
    # 免费用户：允许手工创作
    if tier == "none":
        return {
            "allowed": True,
            "tier": "free",
            "restrictions": {
                "ai_access": False,       # 无 AI
                "project_limit": 1,       # 限1本
                "ai_trial_days": 0,       # 试用已用完
            }
        }
    
    # 有套餐
    if tier in ("monthly", "quarterly", "yearly"):
        try:
            if expires_at and date.fromisoformat(expires_at) < date.today():
                return {"allowed": True, "tier": "expired", 
                        "restrictions": {"ai_access": False, "project_limit": 1}}
        except ValueError:
            pass
        return {"allowed": True, "tier": tier}
    
    return {"allowed": True, "tier": tier}
```

**项目上限控制 (前端 DashboardPage)**
- `GET /api/projects` 返回时，免费用户只显示已有项目，不显示"新建项目"按钮
- 如果项目数 >= 1，显示升级提示

**AI 试用倒计时**
- `config.json` 新增 `ai_trial_start` 字段
- 后端 `verify_session()` 返回剩余试用天数
- 前端 banner 显示试用倒计时

async def api_verify_key(req: ApiKeyVerifyRequest):
    """测试 API Key 是否可用"""
    try:
        client = AsyncOpenAI(api_key=req.api_key, base_url=req.api_base_url)
        await client.models.list()  # 简单测试

## 9. 短篇支持（补充设计）

当前产品只支持长篇（卷→章→6阶段工作流），但目标用户中短篇创作者占比很大。

### 两种模式的差异

| 维度 | 长篇模式 | 短篇模式 |
|------|---------|---------|
| 结构 | 卷 → 章 → 节 | 单篇 / 合集 |
| 工作流 | init → settings → outline → prompt → write → archive | write → edit → done |
| 设定 | 世界观/角色/风格/反AI/伏笔 | 可选（一句话梗概即可） |
| 卷纲 | 必须 | 不需要 |
| 章纲 | 每章必须 | 不需要 |
| 写作周期 | 数月 | 数小时到数天 |

### 短篇模式的改动

**新建项目时选择模式：**
```
┌─────────────────────────┐
│  创建新作品              │
│                          │
│  ○ 长篇（卷章结构）      │
│    6阶段工作流，适合小说   │
│                          │
│  ● 短篇（单篇/合集）     │
│    轻量模式，快速写作     │
│                          │
│  类型: [都市言情 ▼]      │
│  书名: [______________]  │
│                          │
│  [创建]                   │
└─────────────────────────┘
```

**短篇的项目结构：**
```
项目
├── 正文.md              ← 一个文件写到底
├── 梗概.md              ← 可选：一句话/一段话
└── 设定.md              ← 可选
```

**后端改动：**
- `Project` 模型新增 `mode` 字段（`long`/`short`）
- `mode=short` 时跳过 settings/outline 等阶段，直接进入 write
- `mode=short` 时 volumes/chapters 可选

**前端改动：**
- NovelPage 根据 mode 切换 UI
- `mode=short`：隐藏左侧卷章树，换成一篇文章编辑器
- `mode=long`：保持现有卷章结构

| 免费额度 | 长篇 | 短篇 |
|---------|------|------|
| 免费用户 | 1 本 | 5 篇 |

| 购买后 | 不限 | 不限 |
