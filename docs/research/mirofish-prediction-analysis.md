# MiroFish 推演引擎分析 & ai-novel 剧情推演设计

> 调研日期：2026-06-24
> 目标：理解 MiroFish 的推演机制，设计 ai-novel 的剧情推演方案

---

## 第一部分：MiroFish 如何做到推演

### 一、核心理念：涌现式预测

MiroFish 不是通过算法公式或统计模型做预测的。它的核心方法是：**构建一个高保真的平行数字世界，在其中运行模拟，观察涌现结果，以此作为预测依据。**

```
用户输入（文档 + 问题）
     ↓
[世界构建] 知识图谱 → Agent 人格生成
     ↓
[模拟运行] OASIS 多 Agent 社交模拟
     ↓
[结果分析] ReACT 模式报告生成
     ↓
预测报告
```

### 二、五步流水线深度拆解

#### 步骤 1：知识图谱构建（Ontology + Zep）

**输入：** 用户上传的文档（PDF/MD/TXT）+ 一个模拟需求描述

**过程：**

```
文档 → 分块（500字符/块，50重叠）
     → OntologyGenerator（LLM）提取实体类型（恰好10种）和关系类型（6-10种）
     → GraphBuilderService 在 Zep Cloud 创建图
     → 批量发送文本块到 Zep（每批3块）
     → Zep 自动提取实体、关系、构建社区摘要
     → 拉取节点和边完成图构建
```

**关键设计决策：**
- 实体类型必须是「能发声的实体」（人、组织），排除抽象概念——因为后面要让它们当 agent
- 关系类型用 `UPPER_SNAKE_CASE`（如 `WORKS_FOR`），实体用 `PascalCase`
- Zep Cloud 提供：实体提取、语义搜索、临时记忆、社区摘要

#### 步骤 2：环境设置（Agent 人格 + 模拟配置）

**Agent 人格生成（OasisProfileGenerator）：**
```
Zep 图节点 → 过滤（只保留有自定义类型的节点）
           → 为每个节点构建上下文（事实 + 相关节点）
           → LLM 生成：bio, persona, age, gender, MBTI, country, profession, interested_topics
           → 支持并发生成
           → 写入 profile 文件
```

**模拟配置生成（SimulationConfigGenerator）：** 分步、分批次生成：

| 批次 | 生成内容 |
|------|---------|
| 第 1 步 | 时间配置：模拟时长、每轮分钟数、时段划分 |
| 第 2 步 | 事件配置：热点话题、叙事方向、初始帖子 |
| 第 3+N 步 | 每 agent 配置：活跃度、发帖频率、立场、影响力权重 |
| 最后 | 平台配置：Twitter/Reddit 权重 |

**关键洞察：** LLM 为每个初始帖子分配发布 agent（`_assign_initial_post_agents`），根据 agent 类型匹配帖子类型——这不是随机的，是有意图的事件播种。

#### 步骤 3：模拟运行（OASIS 框架 + CAMEL-AI）

**这是整个系统的核心——真正的"推演"发生在这里。**

```
SimulationRunner（子进程）
  → 加载 agent profiles + 配置
  → 创建 OASIS 环境（Twitter 或 Reddit 平台）
  → 注入初始帖子（ManualAction）
  → 主循环：
    每一轮：
      1. 根据时间段判断哪些 agent 活跃
      2. 活跃 agent 调用 LLM 决定动作：
         - 发帖、评论、点赞、转发、关注
      3. 动作存入 SQLite + actions.jsonl
  → 完成后进入等待命令模式（IPC 采访）
```

**推演的本质：** 每个 agent = 独立的 LLM 调用，带有自己的人格设定和记忆。agent 之间的交互产生**涌现行为**——没有人在代码层面写死「如果 X 则 Y」，而是让 agent 们在给定条件下自由互动，观察自然发生的结果。

**可选增强：** ZepGraphMemoryUpdater 把 agent 的活动写回知识图谱，让图「记住」模拟过程。

#### 步骤 4：报告生成（ReACT 模式）

**ReportAgent 是一个自主的 LLM agent，使用 ReACT（Reasoning + Acting）循环：**

```
1. 大纲规划：LLM 生成报告结构（标题 + 摘要 + 2-5 章节）
2. 逐章节生成（每章一个 ReACT 循环）：
   Thought → Action（调用工具）→ Observation → Thought → ... → Final Answer
   每章至少 3 次工具调用
3. 可用工具：
   - insight_forge：深度检索（子查询分解 + 多维度搜索图）
   - panorama_search：广度搜索（全貌 + 历史事实）
   - quick_search：快速语义搜索
   - interview_agents：采访模拟中的 agent（实时 IPC 调用）
4. 章节保存到 Markdown 文件
```

#### 步骤 5：深度交互（采访模式）

模拟运行完后，用户可以直接采访 agent：
- 单 agent 采访
- 批量采访
- 全局采访（向所有 agent 问同一个问题）

通讯通过文件系统 IPC 实现：Flask 写命令文件 → OASIS 子进程轮询 → 响应

---

### 三、MiroFish 的五个关键设计原则

| 原则 | 说明 |
|------|------|
| **1. 实体 = Agent** | 图谱中的每个实体类型节点都对应一个模拟 agent，且有完整人格 |
| **2. LLM 驱动配置** | 所有配置（本体、人格、模拟参数）都由 LLM 生成，非硬编码 |
| **3. 涌现 > 规则** | 不写死推演逻辑，让多 agent 自由交互产生结果 |
| **4. 多渠道分析** | 报告生成时综合图数据 + agent 采访 + 语义搜索，三个信息源交叉验证 |
| **5. IPC 异步架构** | 模拟是长时间运行的子进程，通过文件系统 IPC 通信，不阻塞 API |

## 第二部分：ai-novel 剧情推演设计

### 一、本质差异

| 维度 | MiroFish | ai-novel 剧情推演 |
|------|----------|-----------------|
| 输入 | 外部文档（PDF/MD） | 内部结构化数据（设定+角色+伏笔+已有章节） |
| 知识图谱 | Zep Cloud（需要外部服务） | 已有 storage backend（YAML 文件） |
| Agent 数量 | 10-50 个社交 agent | 3-15 个角色 agent |
| 模拟平台 | Twitter/Reddit 社交网络 | 叙事空间（场景 → 决策 → 后果） |
| 输出 | 社会趋势预测报告 | 剧情走向建议、角色弧光、冲突场景 |
| 交互 | 采访 agent 获得观点 | 询问角色「此时你会怎么做」 |

### 二、前置条件（ai-novel 已具备）

| 前置条件 | 当前状态 | 说明 |
|----------|---------|------|
| **角色数据** | ✅ 已有 `settings/character-setting/{name}.yaml` | 含 appearance、background、personality、values、skills、state_history |
| **世界设定** | ✅ 已有 `settings/world-setting.yaml` | 含 geography、politics、rules |
| **伏笔系统** | ✅ 已有 `settings/hooks.yaml` | 含 active hooks，类型、状态、优先级 |
| **已有章节** | ✅ 已有 `chapters/{ref}.yaml` | 含 outline、prose、status |
| **写作风格** | ✅ 已有 `settings/writing-style.yaml` | 含 narrative_pov、core_principles |
| **AI 客户端** | ✅ 已有 `ai_client.py` | 支持 haiku/sonnet，chat + chat_stream |

### 三、推演架构设计

```
用户触发「剧情推演」
     ↓
┌─────────────────────────────────────┐
│  1. Context Builder                  │
│  ├── 读取当前章节的上下文            │
│  ├── 读取所有角色的最新状态          │
│  ├── 读取活跃伏笔                    │
│  ├── 读取世界设定关键要素            │
│  └── 读取前情提要（最近 N 章摘要）   │
└─────────────────────────────────────┘
     ↓
┌─────────────────────────────────────┐
│  2. 剧情分支生成（LLM 一次性输出）   │
│  ├── 方案 A：基于当前状态的自然发展   │
│  ├── 方案 B：引入外部冲突的转折      │
│  ├── 方案 C：伏笔收束的新方向        │
│  ├── 方案 D：角色驱动的意外发展      │
│  └── 每个方案包含：                  │
│       ├── 走向描述（2-3 句话）       │
│       ├── 涉及角色及可能反应         │
│       ├── 触发的伏笔                 │
│       └── 可能的下一章梗概           │
└─────────────────────────────────────┘
     ↓
┌─────────────────────────────────────┐
│  3. 角色决策模拟（可选深入）          │
│  ├── 选择 1-3 个关键角色             │
│  ├── 注入角色人格 + 当前状态         │
│  ├── 模拟角色在给定情境下的决策      │
│  └── 输出角色内心独白 / 行动计划     │
└─────────────────────────────────────┘
     ↓
┌─────────────────────────────────────┐
│  4. 前端展示                         │
│  ├── 卡片式展示多个剧情走向          │
│  ├── 每个走向可展开查看细节          │
│  ├── 角色决策模拟可单独触发          │
│  └── 选中后可作为章纲填入编辑器      │
└─────────────────────────────────────┘
```

### 五、Prompt 设计

**剧情分支生成 prompt：**
```
你是一位资深小说剧情推演专家。基于以下故事状态，为接下来的剧情发展提供多个可行走向。

## 故事前提
{premise}

## 当前章节概要
{current_chapter_outline}

## 前情提要
{previous_chapters_summary}

## 角色状态
{character_snapshots}

## 活跃伏笔
{active_hooks}

## 世界设定关键要素
{world_setting_key_points}

---

请给出 {count} 个不同的剧情走向。每个走向应该是逻辑自洽、符合角色性格、能推动故事发展的。

对每个走向提供：
1. 标题（一句话概括）
2. 走向描述（2-3 句话）
3. 涉及的角色及他们可能的反应
4. 会触发的伏笔
5. 下一章的章纲建议
6. 情绪基调

确保走向之间有足够差异：一个偏安全、一个偏冒险、一个偏转折、一个偏角色驱动。
```

**角色决策模拟 prompt：**
```
你扮演以下角色，用第一人称回应给定的情境。

角色：{character_name}
性格：{personality}
当前状态：{current_state}
价值观：{values}
技能：{skills}

情境：{scenario}

请以这个角色的身份，给出：
1. 内心独白（ta 此刻的真实想法和感受）
2. 会做出的决定
3. 接下来会采取的行动计划
4. 情绪变化轨迹

不要跳出角色，不要替其他角色做决定。
```

### 八、与 MiroFish 的关键差异总结

| MiroFish | ai-novel 剧情推演 |
|----------|-----------------|
| 多 agent 实时模拟（OASIS） | 单次 LLM 调用生成分支（轻量） |
| 需要外部 Zep 图数据库 | 依赖已有 storage backend |
| 模拟耗时数小时 | 推演耗时数秒 |
| 输出社会趋势报告 | 输出剧情走向建议 |
| 大量 agent（10-50） | 少量角色（3-15） |
| 社交平台交互 | 叙事空间决策 |
| 采访 agent 获得观点 | 模拟角色内心独白 |

**核心差异的原因：** 小说剧情推演不需要高保真社会模拟。作者需要的是「灵感火花」——几个可行的剧情方向，而不是精确的社会趋势预测。因此 ai-novel 采用 LLM 一次性生成多个分支的方式，轻量、快速、实用。角色决策模拟作为深度选项保留，在用户想深入探索某个角色的心理时使用。
