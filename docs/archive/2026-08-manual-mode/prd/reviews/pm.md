# 产品经理评审：爱小说 C 端大改版（PRD v1.0）

> 角色：产品经理（pm-agent）· 2026-08-10
> 范围：非 AI 参与的基础能力 + 页面 UI&UX 设计；免费/PRO 两态体验
> 立场来源：PRD.md / feature-matrix.md / user-story-map.md / manual-mode-review.md / pages/01–04 / reviews/architect.md / reviews/consensus.md
> 视角：产品价值与商业价值，而非技术可行性。判断标准是「小禾怕复杂、老赵恨流程绑架」两条画像下，能力是否真正闭环、是否被砍或超卖。

---

## 1 总体结论

**部分认可。** 「正文工作台 = 唯一主界面 + 免费 = 建书即写 + 一套 UI 两态」的核心范式对两个画像都成立，架构师 C1–C6 的收敛方向在产品上正确；但免费主流程存在两处**闭环缺口**——正文工作台树上没有「新建卷/章」入口、「只显示有正文章节」使空章节不可达——直接击穿 PRD §8 验收#2 与「今天写正文」的承诺，高保真 02 与 PRD 自相矛盾，必须作为 P0 修掉，否则「建书即写」就是超卖。

---

## 2 优点

1. **定位锋利且直击画像**（PRD §1.1/§1.3）：「免费 = 完整人工写作能力；PRO = 同一界面解锁 AI」精准命中小禾（怕复杂）与老赵（恨流程绑架）。「10 秒建书、今天写正文」是有量化标准的好卖点。
2. **「一套 UI，两种状态」是本次改版最该守的红线**（feature-matrix §3）：付费差异收敛到入口可见性与字段显隐，不搞两套页面。从商业上这是防范围爆炸、防双倍维护的正确决策，架构师把它作为所有裁决的锚，认同。
3. **信息去重纪律**（PRD §6）：层级/归档/字数/进度/配置入口各有唯一位置，是对老赵「不被每一步都拦」的直接响应。
4. **提示词重定位干净**（manual-mode-review §2）：提示词 = AI 生成能力的内部环节而非创作流程一步，手动用户全程零打扰。这是「免费 = 纯手写闭环」成立的前提。
5. **配置抽屉「去写正文」一步到位**（PRD §4.3 / 02-writing）：卷/章摘要级抽屉 + 一键直达正文，是「最快到达正文」的最小路径，比旧整页编辑器更符合快速写作心智。
6. **归档只读闭环已在工作台内演示**（02-writing）：归档按钮 → 编辑器 contenteditable=false → 顶部只读提示条 → 树节点 📦 标记与进度卡同步，三处状态一致，闭环方向正确。
7. **C1–C6 整体收敛对产品有利**：设定入口可见可折叠（不砍免费人工能力）、大纲双轨（免费快捷/高级完整）、面包屑限定范围、入口按钮 + 独立视图、两栏保编辑器主战场——逐条均与我作为 PM 的立场一致（详见 §4）。

### P0 — 闭环破坏，必须先修

| # | 问题 | 证据 | 建议 |
| --- | --- | --- | --- |
| P0-1 | **免费正文工作台树上无「新建卷/章」入口，且空章节不可达**。02-writing 左树没有任何「+ 添加卷/章节」按钮（`addVolume` 等 JS 是死的、未挂到任何控件）；同时 PRD §5.2 与 02 头部「正文章节（仅显示有正文的章节）」的过滤使**新建的空章节不显示在树里**。结果：免费用户建书后，在工作台里既没有入口新建章节，也找不到空章节去开写——「建书即写」的第一次写作无处落地。 | PRD §5.2 vs §8 验收#2；02-writing 左树；feature-matrix §3.4「树即一切」与「只显示有正文章节」自相矛盾 | ① 正文工作台树常驻「+ 新建卷」「+ 新建章」入口（与 04-outline 对齐）；② 空章节以「未写」弱化态显示在树中（或新建章时立即创建并直达编辑器，确保回跳也不丢失）；③ 「只显示有正文章节」过滤仅保留在归档/已完成视图。**验收必须补「新建章节即达编辑器」一步。** |

## 5 开放问题立场

### O1 免费限 1 本口径
**立场：v1 保留「限 1 本」，但必须三处显式化，且与定位措辞和解。**
- 理由：单用户本地工具 + 按 Token 计费，免费 1 本是合理的转化杠杆；小禾（从未写完一本）1 本就够，老赵可付费解锁。真正的问题是 PRD/feature-matrix 全程未提，属「隐藏上限」——上限不可怕，隐藏才伤信任，且与「免费 = 完整人工写作能力」存在超卖张力。
- 落地：① 定位措辞改「免费 = 完整人工写作能力（限 1 部作品）」，避免「完整」被读作「无限作品」；② 创建弹窗保留现有「免费用户可创建 1 本小说」提示（01-list 已具备）并升级为转化锚点（「升级 PRO 解锁多本」）；③ 作品列表在满额时展示「已用 1/1，升级解锁更多」，而不是让创建入口神秘消失。
- 兜底：若商业上想降摩擦，可放宽为「免费 3 本」，但不要无限——否则 PRO 转化锚点消失。

### O2 评审缺口
**立场：以「PRD v1.1（按 C1–C6 收敛）+ architect.md + 本 pm.md」作为本次开发基线，frontend/backend 评审允许以现有材料为准。**
- 理由：产品侧立场（feature-matrix + user-story-map + manual-mode-review + 本 pm.md）已覆盖本次范围（免费基础能力 + UI&UX）的全部决策点；ui-design.md + 高保真四页构成 UI 侧证据。frontend.md/backend.md 缺失不阻塞 P0，但 P0 开工前必须解决本评审 §3 的 P0-1/P0-2，否则开发会按 02-writing 蓝本做出与 PRD §8 验收矛盾的实现。

### O6 题材级配置免费可见性
**立场：题材级配置「免费可填、PRO 可消费」，不整区全锁。**
- 理由：题材配置（基调/禁忌/爽点/节奏/弧线）本质是**故事的口味与边界**，是创作约束，不是 AI 参量——一个严肃的人工作者（老赵）完全应该能自己写「禁忌：主角不死、爽点：打脸」而不需要 AI。user-story-map B0.5 也把它描述为「默认带入、可覆盖、可后补」的普通配置。把它整区归 PRO 有两个产品代价：① 人为砍掉免费人工能力，违背「免费 = 完整人工写作」；② 丢掉一个天然 PRO 转化锚点——免费用户填了题材配置，升级 PRO 后 AI 直接消费这些约束，升级动机更强。
- 落地：按字段拆两类——**创作约束类**（禁忌清单、爽点类型、故事弧线模板）→ 免费可见可填（人工边界）；**AI 提示词参量类**（tone blueprint 的引擎映射、节奏规则的 AI 注入）→ PRO。最简口径：**免费可填全部题材配置文本，PRO 增值 = AI 读取并消费这些配置**（生成设定/正文时作为上下文）。这比 architect C1 把题材级配置整体列为 PRO（🔒/隐藏）更符合产品定位，也保留转化钩子。

## 6 验收建议

**免费主流程验收一句话：** 新免费账号只填书名建书后，能在正文工作台树上**新建「第一章」并直达编辑器开写**，自动保存/实时字数/底部进度条可见，归档后只读且树与进度同步，全程零 AI 字段与提示词入口——其中「新建章节即达编辑器」必须作为显式验收步骤（当前 PRD §8 缺这一步，需补）。
