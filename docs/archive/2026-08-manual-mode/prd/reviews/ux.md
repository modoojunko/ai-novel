# 用户体验评审：爱小说 C 端大改版（免费主流程 + 页面 UI&UX）

> 角色：UX 研究员（design-ux-researcher）· 2026-08-10
> 范围：docs/prd/ 下 PRD v1.0 / user-story-map / ui-design / feature-matrix / manual-mode-review / pages/01-04 / architect.md C1–C6 / consensus.md
> 视角：用户怎么用、会不会卡住——从「小禾怕复杂」「老赵恨流程绑架」两个画像检验「建书即写、零打扰」是否真正成立。
> 方法：以高保真四页为可走查对象，逐环节模拟两画像操作路径；交叉核对 C1–C6 裁决的落地一致性。

---

## 1. 总体结论

**「建书即写、零打扰」的方向判断正确，但高保真主工作台（02-writing.html）在「树行内新建卷/章」与「高级配置入口」两处断链——免费主流程照原型走不通，且 C1/C5 已裁决的入口在定稿页面上缺失，落地前必须补齐。**

一句话：方向对，闭环没画完；照 02-writing 的原型走，小禾建完书后会卡在「没有入口创建第一章」，老赵则会在「找不到高级配置入口」和「同一节点两套编辑面」之间多花时间。

## 2. 用户旅程走查（免费主流程）

按 PRD §3.1 免费主流程逐环节，✅ 可走通 / ⚠️ 有卡点 / ❌ 断链。标注「小禾」或「老赵」指出主要受影响画像。

| # | 环节 | 判定 | 理由 |
| --- | --- | --- | --- |
| A1 | 作品列表 → 创建弹窗 | ✅ | 书名自动聚焦 + 回车创建 + 成功直接进正文工作台（01-list）；「继续创作」主按钮清晰。 |
| A2 | 创建弹窗约束提示 | ⚠️ | 「免费用户可创建 1 本小说」（01-list）直接打击爱试错的小禾（O1 未决）；限 1 本与「免费=完整人工写作」定位冲突，且无超限就地反馈示例。 |
| A3 | 创建后落地引导 | ⚠️ | C5 已移除「设定引导卡」，但正文工作台没有任何替代 EmptyState——小禾落地后面临「空白工作台 + 没有下一步」，与 user-story-map A1「知道接下来该做什么」的 AC 相悖。 |
| B1 | 工作台树 · 卷/章 CRUD | ❌ | **02-writing 树上没有任何「添加卷/添加章节」入口**。免费主流程 PRD §3.1「左树管理卷/章」、feature-matrix「树即一切」、architect P2「树行内 CRUD 强化」都要求行内新建，但高保真未画——建书后小禾/老赵都无法创建第一章。**免费流最大断链。** |
| B2 | 树只显示有正文章节 | ⚠️ | PRD §5.2「正文树只显示有正文的章节」→ 新建的**空章会被过滤掉不可见**，用户刚建完章就找不到它去写。即便 B1 补上，此过滤也让「建章→去写」失败。两问题叠加。 |
| B3 | 卷节点点击 → 抽屉 | ⚠️ | 抽屉互斥（开卷关章）实现正确（02-writing `openVolumeDrawer`）；但整行（含 ▾）点击=开抽屉，与树「折叠/展开」语义冲突，▾ 只是装饰，多卷时导航痛苦。 |
| B4 | 章节点点击 → 抽屉 | ✅ | `event.stopPropagation()` 事件不冒泡、抽屉互斥、抽屉内「去写正文 →」一步到位加载编辑器——这是全流程交互最顺的一环，老赵路径的核心亮点。 |
| B5 | hover「配置 →」入口 | ⚠️ | `opacity-0 group-hover:opacity-100` 纯 hover 显现：键盘不可达（违背 NFR「键盘可达」），小禾悬停前无任何可点击线索（整行无下划线/箭头图标）。 |
| C1 | 写正文 · 自动保存/字数 | ✅ | 「编辑中…」→1.5s→「已自动保存 ✓」三态可见、实时字数、底部状态栏——与 ui-design §3.1 一致。 |
| C2 | 写正文 · 保存失败态 | ⚠️ | **失败态与重试无任何原型/示例**。「自动保存」承诺「不怕丢」（E1）若无失败+重试兜底，静默丢内容风险直接击穿小禾核心安全感。 |
| C3 | 专注模式 | ⚠️ | 02-writing 有按钮无行为；Esc 退出、隐藏左右栏、底部状态栏为唯一可见锚点（C6）仅存在于文字 spec，未在原型可验。 |
| D1 | 归档 → 只读 | ✅ | 归档 → 编辑器只读 + 顶部提示条 + 树 strikethrough+📦 同步（02-writing `archiveChapter`）闭环完整。 |
| D2 | 归档状态语义 | ⚠️ | strikethrough（删除线）惯用语义是「已删」，老赵可能误判章节被删；且树（📦+删除线）+ 顶部提示条 + 灰字三重冗余，轻微违背 §6 去重，但冗余在此处利于识别，可保留其一。 |
| E1 | 设定/大纲可达（免费） | ❌ | **02-writing 无任何「高级配置/设定/大纲」入口**——C1/C5 裁决「可见可进、折叠入口」在定稿页面上未实现。免费用户（尤其需要设定帮助的新手）根本无法到达设定/大纲。 |
| E2 | 设定页字段标注 | ⚠️ | 03-settings 免费项标「必填」（简介/世界/风格）与「高级配置 · 可选」定位矛盾——小禾进入可选的设定页却看到必填红标，重燃「被流程绑架」焦虑。 |

**两画像验收结论**：
- 老赵「最快到正文」：创建 ✅ → 建章 ❌（B1）→ 写正文 ✅。**卡在建章一步**，补上 B1 即闭环。
- 小禾「今天见正文」：创建 ✅ → 不知下一步 ⚠️（A3/B1）→ 写正文。**卡在引导缺失 + 建章入口缺失**。

## 3. 问题清单（按严重度）

### P0 — 阻断「建书即写」主流程

**P0-1 工作台树无卷/章新增入口**
- 场景：小禾建完书，进入正文工作台，左侧树只有示例章节，无「+ 添加章节」「+ 添加卷」。
- 问题：免费主流程 PRD §3.1「左树管理卷/章」与 feature-matrix「树即一切」要求行内新建，但 02-writing 高保真完全没有该入口；行内新建章（带输入行）只存在于 04-outline（高级配置大纲视图）。免费用户被迫先去「大纲」建章才能写正文 → 直接违背「建书即写、零打扰」。
- 建议：工作台树补充「+ 添加章节」（行内输入，参考 04-outline 的 `chapter-add` 交互）与「+ 添加卷」（弹窗）。这是免费流 P0，必须在主界面闭环，不能依赖高级配置视图。

**P0-2「只显示有正文的章节」过滤吞掉新建空章**
- 场景：用户在树上新建一章（尚无正文），树按 PRD §5.2 过滤「只显示有正文的章节」→ 新章立即消失。
- 问题：用户找不到刚创建的章节，无法点选进入写作；「建章→去写」逻辑自相矛盾。与 P0-1 叠加是免费流最大死点。
- 建议：改为「树显示全部章节，空章弱化为『待写』空态（灰色 + 未写标记）」，或新建章时立即生成空 prose 文档使过滤规则自然通过。不要用「过滤+隐藏」处理空章。

**P0-3 主工作台缺失「高级配置」入口（C1/C5 未落地）**
- 场景：免费用户想补设定/大纲（或老手想配卷纲），主界面没有入口。
- 问题：C1/C5 裁决「设定/大纲 = 次级折叠入口，免费可见可进」在 02-writing 完全未体现（小说栏只有书名/类型/免费提示）。「消失的入口不教育用户」——architect 自己反对隐藏，但定稿高保真恰好把它隐藏了。免费「完整人工写作」被架空，PRO 转化锚点消失。
- 建议：在小说栏右侧放「高级配置 ▾」折叠入口（含「设定 / 大纲」两项），并让工作台空态 EmptyState 顺带给出该入口的次级链接（两处候选位取一收敛，避免 consensus §6 的双候选不一致）。

### P1 — 明显卡顿/心智负担

**P1-1 C3 双轨制造两套编辑面，且无抽屉→全字段跳转**
- 场景：用户在正文工作台点章节点开抽屉（2 字段），想填 key_points/情绪设计却找不到；或 PRO 用户升级后发现「同一节点，两种编辑面」。
- 问题：工作台抽屉（卷名+摘要/章名+摘要）与高级配置大纲面板（全字段）服务同一数据、两套 UI，无任何从抽屉进入全字段的路径；用户只能凭经验猜测「全字段在『高级配置·大纲』」。两视图的节点状态语言也不一致（见 P1-4）。
- 建议：抽屉底部增加「查看/编辑完整字段 →」跳转高级配置大纲视图并定位到该节点（符合 C3「以视图上下文区分」但不设死胡同）；抽屉顶部的「免费模式=卷名+摘要，高级字段属 PRO」注记对免费用户易被读成「与我无关」，应改成「更多字段 → 高级配置·大纲」。

**P1-2 保存失败态缺失**
- 场景：磁盘满/写入异常，自动保存失败，UI 无提示。
- 问题：ui-design §3.1 定义了「保存失败 error + 重试」，但 02-writing 只有「编辑中/已自动保存」两态；失败静默 = 小禾「不怕丢」承诺失效。
- 建议：补第三态「保存失败 + 重试按钮」（复用保存三态，与现有 ChapterEditor 状态机一致），并加网络/磁盘错误全局兜底提示。

**P1-3 新建书无 EmptyState 引导**
- 场景：小禾创建成功，落点空白工作台（C5 已移除设定引导卡）。
- 问题：user-story-map A1「知道接下来该做什么」的 AC 在免费流无承接；空白树 + 空编辑器 = 无下一步线索。
- 建议：正文工作台空态 EmptyState：「创建你的第一章」主按钮 + 「高级配置 · 可选」次级链接 + 一句「先写正文，设定随时补」。

**P1-4 两视图节点状态语言不一致**
- 场景：同一章在 02-writing 树显示「未归档/已归档/字数」，在 04-outline 显示「待配章纲/已确认/未填写」。
- 问题：写作状态（draft/进行中/已确认/已归档，user-story-map E2）与章纲状态（outline_status）混用，用户跨视图对比时会产生「这章到底确认没确认」的困惑。正是 consensus O4 未决项。
- 建议：工作台树只显示**写作状态**（字数+归档），大纲视图只显示**配置状态**（待配/已确认）；若同屏出现须分组并加图例，禁止两种状态并排在同一个节点徽标区。

**P1-5 免费用户进入设定页见「必填」标注**
- 场景：小禾被 C1 入口引导进设定，看到简介/世界/风格标「必填」。
- 问题：必填是 PRO 门控语义，免费模式下设定是「可选高级配置」，红标制造焦虑且与顶部「可选」标注自相矛盾。
- 建议：免费 tier 下把「必填」改标「建议填写」或「PRO 上下文」；「必填」仅在 PRO 门控语境展示。

### P2 — 细节/可及性

| # | 场景 → 问题 → 建议 |
| --- | --- |

| # | 裁决 | UX 影响确认 |

| C1 | 设定免费可见但折叠 | ✅ **方向正确**——「消失的入口不教育用户」成立；但落地缺失（见 P0-3），且免费字段需配套 P1-5 的「必填→建议」改标，否则可见反而制造焦虑。 |

| C4 | 面包屑仅工作台 | ✅ 正确；专注模式下面包屑是唯一层级锚点。补充：专注模式若隐藏面包屑则锚点消失，建议**专注模式保留面包屑栏**（只藏树+右栏）。 |
| C5 | 入口按钮 + 独立视图，写作恒默认落点 | ❌ **裁决方向正确（写作恒落点=老赵核心诉求），但高保真未实现该入口**（P0-3）。且「小说栏设定(PRO)按钮」与 prototype 次级入口条两候选位不一致，需收敛一处再落地。 |
| C6 | 两栏 + 底部进度条 | ✅ 对 1280×800 正确，正文空间优先；底部进度条在专注模式下是唯一持续可见进度锚点——好设计。**但 02-writing 仍是三栏（含右侧 22% 进度卡），高保真与裁决不符，需收敛。** |

## 6. 一句话验收建议

**以一条纯手动路径作为本次改版的唯一验收红线：「小禾 10 秒建书 → 工作台树『+ 添加章节』→ 直接写出第一段并看到『已自动保存 ✓』→ 归档后只读」，凡在此路径上多一步点击、多一次切换视图、多一个隐藏入口（hover 才可见/折叠里再折叠）即为失败。**
