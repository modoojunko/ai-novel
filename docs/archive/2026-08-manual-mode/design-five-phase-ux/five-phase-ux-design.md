# 五段创作流程体验设计方案

> 三视角协作产出：产品梳理（PM）· 交互设计（UX）· 视觉设计（UI）
> 范围：创建小说 → 配置设定 → 配置卷纲 → 配置章纲 → 写正文
> 状态：待评审（设计稿，未实施）

---

## 一、产品梳理（PM 视角）

### 1.1 体验目标（每段 2-3 条，可衡量）

| 环节 | 体验目标 |
| --- | --- |
| 创建小说 | 10 秒内完成建书；创建后 100% 新用户知道下一步做什么 |
| 配置设定 | 7 项设定进度一目了然；用户能区分"必填"与"可后补"；完成确认有即时反馈 |
| 配置卷纲 | 保存/失败反馈即时可见；完成卷纲后引导进入章纲 |
| 配置章纲 | 确认入口无需寻找；缺什么就地可见并可跳转补齐 |
| 写正文 | 连续写作 30 分钟不疲劳；本章字数/进度随时可见；切换章节上下文不丢失 |

### 1.2 用户故事与验收标准（要点式）

**创建小说**
- 新手：我要在 10 秒内建好一本书，并知道下一步该做什么。
  - AC：输入书名 → 回车创建 → 进入工作台并自动定位到「设定」，顶部出现引导条（已有 OnboardingCard 增强版）。
- 老手：我不想每次都被引导打断。
  - AC：引导条可关闭，且本次会话不再出现（会话级，已有逻辑）。

**配置设定**
- 新手：我要知道 7 项设定填到哪一步了，哪些可以以后补。
  - AC：顶部进度条显示"设定 n/7"；每项树节点带状态徽标（未填/进行中/已确认）；可后补项（如伏笔）有"可后补"标注。
- 老手：确认一项就要有反馈，不能点了没反应。
  - AC：点「确认完成」成功后节点变绿 + toast"已确认"；失败给原因。

**配置卷纲**
- 用户：我保存卷纲后要知道是否成功，然后知道下一步。
  - AC：保存按钮状态机（保存中→已保存✓→失败可重试）；卷创建后出现「去配章纲」次级按钮。

**配置章纲**
- 用户：我要知道哪个章节缺什么、在哪确认。
  - AC：章卡片底部固定「确认章纲」主按钮；缺必填字段时按钮旁提示"缺：情感基调、必要变化"，点击滚动到对应字段。

**写正文**
- 用户：我要舒服地长写，并知道进度。
  - AC：字号/行距可切换（3 档）；专注模式一键隐藏侧栏工具栏；底部常显"本章 xx 字 / 目标 xx 字"。

### 1.3 优先级

| 级别 | 事项 | 理由 |
| --- | --- | --- |
| P0 | 设定完成度指示（进度+徽标） | 直接解决"7 项不知道填到哪"的核心困惑 |
| P0 | 卷纲保存反馈 + 下一步引导 | 无反馈=不确定=焦虑，低成本高感知 |
| P0 | 章纲确认入口强化 + 缺字段就地提示 | 确认是阶段闸门，可发现性直接影响推进 |
| P0 | 创建后下一步引导增强 | 新用户第一印象，决定留存 |
| P1 | 正文字号/行距/专注模式 | 长时写作舒适度，中等成本 |
| P1 | 字数/进度统计 | 老手回访路径的价值感 |
| P1 | 章节切换上下文提示 | 防止"忘了写到哪" |
| P2 | 书名校验、其他打磨 | 边际收益低 |

### 1.4 明确不做
- 不做 AI 相关（阶段 2 暂缓）
- 不做导入入口（另行安排）
- 不改六阶段结构、不改后端 API
- 不做移动端适配（桌面应用）

## 二、交互设计（UX 视角）

### 2.1 创建后引导（成本：低）
现状：CreateProjectModal 成功后进入工作台，OnboardingCard 显示六阶段步骤条。
改进：创建成功 → 自动切到「设定」tab；OnboardingCard 增强为"设定进度卡"——标题"完成设定，开启你的书"，正文"已确认 n/7 项"，主按钮「继续设定」，并保留「先写起来」旁路。

### 2.2 设定完成度（成本：低）
现状：settings 树节点仅有确认状态，无整体进度；确认后仅状态变化。
改进：
- 顶部（tab 栏下方或设定面板头部）加紧凑进度条：`设定 n/7`，完成变 success 色。
- settings 树节点加状态徽标：未填（ghost）/进行中（warning 点）/已确认（success 勾），复用 TabProgressButton 的视觉语言。
- 可后补项（伏笔/角色）标签旁加"可后补"小字，降低压力。

### 2.3 卷纲保存反馈 + 下一步（成本：低）
现状：VolumeEditor 保存按钮只有"保存中…/保存"，无成功态。
改进：按钮状态机对齐 OutlineEditor（保存中 spinner → 已保存 text-success → 失败 text-error + 重试）；保存成功后 2 秒提示条"已保存"；创建卷成功后出现次级按钮「去配章纲」（切到章纲 tab）。

### 2.4 章纲确认入口（成本：中）
现状：确认按钮存在但层级弱，缺字段时无就地提示。
改进：
- 章卡片底部「确认章纲」用 btn-primary（可带锁定图标），未确认章节卡片边框加 primary/20 强调。
- 缺必填字段时按钮旁 text-error 小字："缺：情感基调、必要变化"；点击滚动到该字段并高亮（参考 GateBanner「去补充」交互）。

### 2.5 正文舒适度（成本：中）
现状：ChapterEditor 无排版控制、无字数统计、无专注模式。
改进：
- 编辑器工具栏加「字号（小/中/大）+ 行距（紧凑/舒适/宽松）」切换，状态存 localStorage（每用户偏好）。
- 专注模式按钮：隐藏左侧树 + 右侧工具栏，正文区全宽居中（max-w-3xl），再次点击恢复；Esc 也可退出。
- 编辑器底部状态栏："本章 xx 字" + 保存状态（复用现有自动保存状态）。

### 2.6 旅程串联
建书 → 设定（进度 0/7，引导卡）→ 卷纲（完成→去配章纲）→ 章纲（确认→去配提示词）→ 正文（专注写作）。每步完成即出现下一步入口，形成闭环，避免用户"不知道去哪"。

## 三、视觉设计（UI 视角）

### 3.1 设定完成度指示器（成本：低）
- 进度条：daisyUI `progress progress-primary h-1.5`，完成态 `progress-success`；右侧文字 `text-xs text-base-content/50`："设定 n/7"。
- 树节点徽标：`badge badge-xs`——未填 `badge-ghost text-base-content/30`；进行中 `badge-warning`（带小圆点）；已确认 `badge-success`（带 ✓）。与 TabProgressButton 状态语言一致。
- "可后补"标注：`badge badge-ghost text-[10px] text-base-content/40`。

### 3.2 卷纲保存反馈（成本：低）
- 统一按钮状态机样式：保存中 `btn-primary loading`（spinner）；已保存文字 `text-success` + ✓（2s 后回"保存"）；失败 `text-error` + "重试"。沿用 OutlineEditor 现有样式，保证两处一致。
- 「去配章纲」次级按钮：`btn btn-outline btn-sm`，带 ArrowRight 图标。

### 3.3 章纲确认（成本：中）
- 主按钮：`btn btn-primary btn-md`，前置 `CheckCircle2`（未完成 `Lock`）；与现有「确认全部章纲」区分层级（主按钮是单章确认）。
- 缺字段提示：`text-xs text-error/90` + 字段名 chip（`badge badge-outline badge-error`），点击聚焦。
- 未确认章卡片：`border-primary/20` 微强调；已确认：`border-success/30` + 顶部成功色小条。

### 3.4 正文排版与专注模式（成本：中）
- 字号三档：15px / 17px / 19px（`prose` 类 + 内联样式或 CSS 变量），默认 17px。
- 行距三档：1.8 / 2.0 / 2.2，默认 2.0（中文阅读舒适）。
- 正文容器：专注模式 `max-w-3xl mx-auto`，普通模式保持现有宽度。
- 专注模式按钮：`btn btn-ghost btn-sm` + `Maximize2`/`Minimize2` 图标，title"专注模式"。
- 底部状态栏：`text-xs text-base-content/40`，左侧"本章 xx 字"，右侧保存状态（复用现有自动保存文字）。

### 3.5 一致性约束
- 全部使用 daisyUI 组件与现有暖色变量（primary/success/warning/error），不引入新色板、新字体。
- 新增状态均以现有组件语言（TabProgressButton 状态、OutlineEditor 保存状态机、GateBanner 跳转交互）为基准，避免视觉碎片化。

## 四、实施建议

1. 先做 P0 四项（创建引导、设定完成度、卷纲反馈、章纲确认），每项都是 1-2 个文件的小改。
2. P0 完成后浏览器实测五段流程，再进入 P1（正文舒适度/字数/专注）。
3. 每段改动保持"只增组件、不动结构"，后端零改动。
