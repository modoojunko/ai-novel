缺口 5 · 空态解剖：出路必须成为类型约束

「禁止只有插画没有出路」写进规范容易，落实靠组件签名。EmptyState 把主动作做成可选属性——可以不传，但一旦界面上没有出口，就一定是你删掉的，不是漏写的。

缺口 6 · 确认弹窗：让 window.confirm 从主流程里消失

五处脏守卫仍用原生 window.confirm：不可主题化、不能放盘点信息、与自研弹窗并存在同一个动作流里，是视觉语言最大的破口。 方案与 toast 同构：挂一次 <ConfirmHost/>，业务里一行 await confirmAction(...)，不需要为每个调用点维护 state。点下面的按钮试试。

左例对应 L2 删除分级；右例替代现有 5 处脏守卫的原生弹窗
// 挂载一次（ClientShell 内，与 <Toaster/> 同层） <ConfirmHost /> // 业务代码：异步、可等待、无本地 state const ok = await confirmAction({ title: "删除这个模型配置？", body: "删除后使用它的书将失去 AI 能力，需要重新选择模型。", tone: "danger", confirmLabel: "删除", inventory: ["3 本书正在使用", "本月已产生 12 万 Token 用量"], }); if (!ok) return; // 口径沿 Modal：hideClose（确认族无 X）；Esc 与点遮罩 = 取消，方向安全

三、反馈层：已有的两个件维持原样

Toast（不要改）

瞬态反馈仍是 toast.*；成功提示靠文字不加图标，错误必须带原因前缀。这是语义分工：Toast 说结果，Notice 说处境，Confirm 要决定。

UndoToast（建议泛化参数）

现在是 api-config 私有件。把 configName 泛化成 name、加 label="删除"，就能推广到 L1 行级删除与 L4 软删除（规范 §12）。8 秒窗口不变。

四、明确不建议抽的

候选为什么不抽
Button 包装组件CSS 档位齐全且类名即语义；包一层会让 IDE、grep 和 design-lint 同时失明
Input / Textarea 封装同上，且表单字段族已在 settings 里成型，重复造一套只会分叉
Tabs / Segmentedmodnav 页签、章内页签、段落行三处形态差异是真的，强行统一会逼出参数地狱
Field 字段组件搬家到 ui/先把 settings/FormField 的导出开放出去即可；等第一个非设定场景真实引用再谈移动

判定标准就是仓库自己的那条：「资深工程师会说这过度设计了吗？」以上四个都会。
