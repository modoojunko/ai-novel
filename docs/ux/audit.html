应用使用 HashRouter（main.tsx:13-19），所有地址实际是 #/…。真实屏只有 5 个，其余都是重定向或壳层状态。

  • 设定：两栏（左栏进度导航 8+1 项 / 右侧面板），另有右轨 AI 卡（主线向导 / 字段级 AI 帮填说明）。
  • 预览：两栏只读（树 + 通读排版）。

结构性缺口：没有兜底路由。App.tsx:26-38 缺 <Route path="*">——任何未知地址都会得到「Navbar + Footer + 空白内容区」，无解释、无出路。

二、用户使用路径

2.1 主干旅程（新建一本书写完一章）

落地页 ──登录──▶ 浏览器授权 ──成功──▶ 书架(空) │ 新建作品（只填书名） ▼ 工作台(免费默认视图=写作, PRO 则见引导卡) │ 写作视图空态：「在左侧树头点＋添加第一卷」 ├─ 设定视图 ──确认完成──▶ (PRO 引导卡推进) ├─ 树 ＋ 添加卷 → 行内加章 ├─ 点章 → 默认落「章纲」页签（点章强制归位章纲） │ ├ 填六必填 → 缺项 chip 就地定位 │ ├ 保存草稿（无缺项时自动升级为已确认） │ └ 「去写正文」→ 切正文页签并聚焦 ├─ 正文：手写自动保存 / （PRO）AI 生成正文流式写入 └─ 归档本章 → 只读锁定 → 树/预览同步标记

2.2 六条支线

支线路径关键节点 / 分叉条件
S1 免费用户边界书架满额 → 入口消失非会员且已有 1 本书时，头部「新建」「导入」按钮整体隐藏（NovelListPage.tsx:155,218）；AI 能力走「入口可见、使用拦截」：.rail-locked 变灰卡 + 后端 403 member_required 触发全局 MemberBlockPrompt。
S2 付费开通UpgradeModal → S 端门户外跳入口三处：novelbar 升级按钮、Rail 锁定卡、BookPrefsModal 账号行；confirm 解析门户 URL 外开新标签，弹窗 locked 防中途关闭。
S3 导入既有稿子导入弹窗两步：上传 → 结构预览.md/.txt/.docx ≤10MB；可返回修改 / 重置为原始结构 / 确认入库；导入后引导卡换成三条短链路（设定 → 提示词 → 写作）。
S4 模型接入/config 添加配置 → 书内绑定模型八家供应商瓦片选择自动填 Base URL；卡片七态健康徽标；删除带影响盘点 + 8 秒撤销；书内在 ModelSettingForm 按 optgroup 选模型，变更可回滚（时间线「恢复」）。
S5 PRO 提示词闭环AiModal 两段式 → 流式 → 质检横幅组装提示词 → AI 润色 → 过目编辑 → 生成；停止保留半成品；生成后出字数达标/未达标 + 七条叙事自查（非阻断、可关闭）；润色/扩写走双栏对比弹窗（Enter 接受）。
S6 长篇循环章 → 归档 → 下一章归档只读后想再动正文 → 任一 AI 写入工具触发「解除只读并继续」解锁链（原动作自动续跑）；版本历史支持行/词 diff 与恢复；modnav 计数随确认进度实时变化。

2.3 阶段机与门控（init → settings → outline → prompt → write → archive）

六个阶段不是六张路由页，而是同一本书里的三层东西：书架上的阶段徽标（PHASE_STAGE 映射成 设定中/写作中/已归档）、PRO 才挂载的阶段催促卡、以及真实的页面内流转。对外口径已拍板为建书 → 设定 → 大纲 → 章纲 → 写作 → 归档，「提示词」是内部环节。

流转UI 触发硬门槛
建书 → 设定引导卡「开始设定」（仅 PRO 挂载）/ 手动点 modnav 设定—
设定 → 大纲/写作SettingsView 底部「确认完成」（校验题材+简介非空才放行）软门（不拦手动切 tab）
大纲 → 写作OgPane「去写正文」章纲六必填齐才能「确认章纲」（缺项按钮禁用 + chip 定位）
写作 → 归档工具栏「归档本章」本章字数 > 0 且未归档
任何 → 离开表单五处 dirty 守卫全部用原生 window.confirm见 §4-J 问题 F7

四、逐页评估

每一屏按「它的使用场景是什么 → 现在做成什么样 → 哪些地方和场景冲突」来评。严重度：高 会造成错误认知或功能断裂；中 增加理解成本或不一致；低 打磨项。

A. 落地页与登录页

场景定位

落地页面向两类人：怕复杂的新手小禾（10 秒建书写起来）、讨厌流程绑架的老赵。登录页是桌面壳唯一的身份入口，主流程只有一步「打开浏览器授权」。

评价

  • PRD 的四原则（永远知道下一步 / 状态可见 / 允许旁路 / 正文优先）与文案基调「人铸灵魂，AI 行笔墨」已经贯彻到落地页结构（痛点支柱 → 怎么用 → 功能 → 定价）。
  • 登录页把慢冷启动处理得体面：静默检查转圈、超 2 秒给「正在唤醒云端服务…约需 30–60 秒」、超时可重试、登出态用 sessionStorage 防自动登录回环。
  • landing.css 声明只用基础令牌派生，但实际出现了三色渐变标题等新表达（见问题 A2）。

问题清单

中
A1 第三档按钮尺寸未入词汇表 — landing.css 新增 .btn-lg（42px 高，圆角 11px），超出现有 sm/xs 阶梯，圆角也不落在既有 token 上。
低
A2 渐变文字是孤例 — .mkt-grad-text 用 accent-strong→accent→ok 三色混合，全站没有第二处同类表达；若保留应登记为营销皮专属令牌。
低
A3 光斑装饰使用裸 arbitrary 尺寸 — w-[900px]/h-[700px] 等已登记豁免，属可接受债务但建议收敛成一个 --hero-blob 类。
中
A4 冷启动文案承诺具体秒数 — 「30–60 秒」写在界面上，一旦常态变快反而显得慢；建议改为描述性措辞 + 可重试。

B. 模型配置页（/config）

场景定位

用户唯一要做的「技术活」。心智负担必须最低：加了几个 Key、哪个能用、花了多少，一眼读完。

评价

  • 信息架构正确：.notice 常驻提醒 → 迁移横幅（一次性）→ 用量看板（三块统计 + 各配置条形 + 环形图）→ 配置卡网格。
  • 卡片七态健康徽标（连接正常 / 认证失败 / 连接超时 / 网络错误 / 频率限制 / 未知 / 未测试）且边框颜色随严重度联动——这是全站最完整的状态语言范本，应当被提炼为通用规范（已在配套规范 §5 收录）。
  • 唯一一处软删除 + 8 秒撤销（UndoToast）出现在这里，设计价值高但没被推广到删书/删题材。
  • Ollama 免 Key 特例、编辑态「留空则保留当前密钥」等文案写得清楚。

问题清单

高
B1 .spin 在 book.css 中被覆盖 — model-config.css 定义了 .spin（rotate 0.8s），book.css 又定义一次（rot 0.9s），按加载顺序后者全局生效。同名不同值，属于等待视觉随加载顺序漂移。
中
B2 .panel 一词两义 — 此处是白色描边卡，book.css 里被整体清零变成裸 660px 栏。同名类靠作用域打架，词汇表应当拆名（详见规范 §6）。
中
B3 本屏节奏偏移未经令牌化 — main 上边距 44 vs 48、page-head 下边距 28 vs 36、empty 56 vs 64、cards gap 16 vs 20，虽有注释声明是有意为之，但没有用变量登记，新屏无从参考基线。
中
B4 鉴权由 useEffect 兜底 — 先渲染一帧再跳登录，与 AuthGuard 的同步 Navigate 不一致，会有闪现。

C. 书架（我的作品）

场景定位

回访用户的枢纽屏：认出自己的书、接着写。同时承担会员状态告知（试用剩几天 / 过期 / 没 Key）。

评价

  • 书卡三件套干净：书名 serif、阶段徽标（设定中/写作中/已归档）、meta（n 章 · 更新于），悬浮 ⋯ 菜单带 :focus-within 键盘可达。
  • 四类横幅条件互斥处理得当（过期覆盖试用），文案向用户语言翻译到位。
  • 空态给「导入 / 开始新小说」双按钮，符合「允许旁路」。

问题清单

高
C1 免费满额时入口直接消失 — 非会员有了 1 本书后，头部「新建」「导入」按钮整体隐藏。用户不知道自己撞了额度墙，只知道「没法建新的」，也没有升级出口在原地。违反 v2 自己的原则「免费/PRO 仅差 AI 入口的显隐，不改变操作路径」。
中
C2 会员判定逻辑重复实现 — 书架本地自算 isMember/freeLimitReached（:124-137,:155），而书内走 LicenseProvider；两条口径并存，未来套餐规则一改就要改两处。
低
C3 多横幅同现无堆叠规则 — 试用中 + 未配 Key 会上下叠两条 notice 条，没有间距/层级约定。

D. 书工作台壳层（novelbar + modnav）

场景定位

写作中的顶栏，要求「存在但不打扰」：随时知道这本书是谁、是不是 PRO、整体进度到哪了。

评价

  • modnav 把完成度计数放进导航本身（设定 n/8 · 写作 n/n 章纲）是「状态可见」原则的最佳落地，成本低、收益大。
  • novebar 的免费提示句「免费模式 · 写作功能完整，升级解锁 AI」一句话说清商业模式与用户无损的关系。
  • 右侧 side 文案随视图切换解释当前模块用途。

问题清单

高
D1 免费用户没有任何引导 — OnboardingCard 与阶段催促都挂在 ProContainer 内，免费态整棵树返回 null（ProContainer.tsx:11）。结果是「新手第一印象决定留存」这个 P0 目标只对 PRO 生效；免费新用户进工作台只看到一棵空树和一个空态面板。
中
D2 双击改名不可发现 — 仅靠 title 属性悬浮提示，鼠标用户几乎不会碰到；与书架上的 RenameModal 路径并存，行为不一致。
中
D3 离开设定视图用 window.confirm — 原生对话框无法主题化、无法图标化，且与全站自研 Modal 确认族（确认族无 X）的视觉语言割裂。
低
D4 modnav 计数用了 /8 与「章纲」混排 — 「写作 n/n 章纲」里数字语义（已确认/总数）需要读两遍才懂，建议徽标改为「章纲 已确认n/总n」。

E. 大纲树与卷纲面板

场景定位

左树是全书的空间感来源（几卷几章写到哪）；卷纲面板是结构规划的重表单，服务于老赵这类愿意做规划的用户。

评价

  • 树的交互完备且克制：展开箭头、笔形行内改名、行内加章（防重复提交）、三态圆点、已归档标签、分级删除确认（内容盘点 chips 用 live 字数防旧值漏报）。
  • 「确认全部已填章节」批量动作有诚实的失败反馈——被 400 拒绝的章节会被跳过并在 toast 里说清楚。
  • 卷纲面板字段分组明确（摘要 / 结构模板 / 弧线三联 / 信息差 / 阶段分配 / 冲突阶梯 / 章节规划 / 角色发声），保存后「去配章纲」直达下一个未确认章。

问题清单

高
E1 目标字数默认值两套口径 — OgPane 本章目标字数「留空默认 2500」，Rail 进度卡无数据时回落 2000。同一个概念在同一本书的两个可见位置显示两个数，用户无法判断哪个是真的目标。
中
E2 三态圆点无图例 — 未填空心 / 进行中实心琥珀 / 已确认实心绿，首次使用者只能猜；目前靠 hover 无补救。
中
E3 卷纲头固定挂「草稿」警示徽标 — 产品模型里卷没有状态位，于是所有卷永远显示 warn 徽标，警示语义被日常化，真正需要警惕的状态反而失去对比度。
低
E4 子表行的删除即时生效 — 冲突阶梯 / 章节规划的行删除无确认也无撤销（对比 /config 有 UndoToast）。数据密度高的表格误触成本不低。

F. 章对象工作台（章纲 / 提示词 / 正文）

场景定位

核心创作现场，单次停留可能 30 分钟以上。「正文优先」原则的主战场：排版舒服、状态安静、AI 不添乱。

评价

  • 正文排版正确地用了宋体 17px/2.0/首行缩进 2em，加字号行距三档（per-book 持久化）与专注模式（Esc 退出），符合长时写作要求。
  • 保存状态四态聚合清晰（保存中 / 未保存 / 保存失败·可点击重试 / 已自动保存），是这个产品最成熟的微状态之一。
  • 章纲表单做了真正的渐进披露：七组折叠 + 必填契约前置（六项）+ 缺项 chip 点击滚动定位并闪烁聚焦 1400ms；「读者获得」缺失只是提醒不拦截，和「允许旁路」一致。
  • 流式生成的边界处理周到：生成期间锁编辑、停止保留半成品、AbortController 随卸载清理、质检横幅永远可关闭。

问题清单

高
F1 润色对比弹窗字体变量失效 — ContrastPreviewModal.tsx:31 写了 var(--font-serif)，而地基里只有 --font-display/--font-body/--font-mono。这个「给作者看成稿质感」的阅读界面正悄悄退化成正文字体。
中
F2 点章强制回到章纲 — 每次选中章节都重置为 og 页签。对「就是想回来改正文」的回访者是一次多余点击；建议记忆每章最后停留页签。
中

K. 横切系统评估（色彩 / 字阶 / 几何 / 图标 / 门禁）

维度现状结论
色彩单一亮色主题；墨绿 accent + ok/warn/err 三状态色，全部 oklch + color-mix 派生 soft 档；soft 混合比不等距（12%/14%/16%/12%）但有意为之；z-index 单调有序（10/40/50/60/80）但未令牌化。骨架健康。待办：把 z-index 与 soft 比例写进令牌注释；不需要暗色主题（已有决议），但 moon 图标仍在注册表内应清理。
字体display 宋体栈 / body 苹方系栈 / mono 数字栈三分清楚；但没有任何 webfont 被真正加载——Noto Serif SC 等四个栈都是回退第一，parity 截图验证的是宋体回退而非意图字形。需拍板：要么打包子集化的 Noto Serif SC（宋体标题才名副其实），要么把栈写实为 Songti SC 打头并在 design-language.html 注明。
字阶全站 22 个字号字面量，10–14px 区间以 0.5px 步进；无命名档。最大债项。规范 §3 给出了合并映射表（22 → 8 档），迁移必须走「先改原型 → 再改实现 → parity 重跑」的既定流程。
圆角命名档只有 --radius 10 / --radius-lg 16；此外还有 6/7/8/9px 四个近似裸值各十来处，999px 胶囊圆角出现 25 次却没有任何 token。补 --radius-sm 与 --radius-pill 两枚即可收敛（规范 §4）。
徽标 / 胶囊13 种实现（.b/.badge/.chip/.genre/.genre-tag/.arch-tag/.tag-plan/.ai-tag/.m-chip/.inv-chip/.gap-chip/.defer-tag/.pill-pro…），共同点是 999px 圆角 + 10–11.5px 字号，差异在内边距与语气色。第二债务项。规范 §6 定义统一的 .pill 家族（.pill-dot/.pill-status/.pill-tag/.pill-pro），迁移按屏走 parity。
图标自研注册表 38 个 path + 8 供应商图；lucide 与 emoji 明确禁止；尺寸一律由父容器类控制（.btn svg 15 / .icon-btn 15 / .btn-xs 12）。方向正确。缺一条「新增图标先登记 path 再使用」的流程约束；ArcWizard 的 ✓/✗ 是存量违规点。
无障碍全局 :focus-visible 描边 + .btn 专属 offset；hover 出现的操作都配了 :focus-within；aria-label ×14 等；但输入框用的是 :focus（鼠标点击也画圈），流式生成 / 自动保存缺 aria-live。两处要修：输入态改 :focus-visible 口径；生成与保存状态补 polite live region（不打断朗读顺序）。
门禁通道内联 style 约 234 处 / 48 个文件，基本都用 token 正确取值，但绕过了组件类与任何 lint 规则；design-lint 严格范围 29 个文件 ≈ 全站的 1/3。第三债务项。建议 lint 增加「内联样式属性命中既有组件类即告警」一层，逐步收编剩余屏。
