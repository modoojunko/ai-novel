〇、结论速览

你要的「全库一致、绝大多数组件相同、特殊场景除外」——地基已经做到了。S 端 src/design/base.css 头部注释写明「C端原样移植 · oklch token 一字不改」，逐字比对属实：令牌表、按钮六档、弹窗版式、表单基座、toast、appbar、统计瓦片全部同源。剩余工作量不是「从零统一」，而是两件事：

① 收敛 8 处语义漂移

同一对象在两端叫不同名字、语气档位不齐、或一端有一端无（徽标 / 提示条 / 表单错误态 / 骨架屏 / 面板卡 / toast 警告档 / on-accent 文字色 / 空态动作槽）。每处都给出了裁决方向与涉及文件清单。

② 建立防再漂移机制（最大风险点）

目前「同源」靠人肉复制粘贴，没有任何自动校验——下一次任何一端改按钮圆角，另一端就会悄悄走样且无人发现。方案是给共享段打上标记注释并新增 design:cross 校验脚本，不一致即门禁失败。

一、三层契约模型：什么必须一样，什么允许不一样

「除了特殊的场景，绝大多数组件都一致」要可执行，就必须先把「一致」拆成三档义务等级：

L1 契约层必须逐字相同
令牌 :root 段（色彩/字体/圆角/阴影）· 基础组件类：.btn 六档与四变体、.icon-btn、.field/.input/.hint、.scrim/.modal/.mcard 五件套、.toast-wrap/.toast、.appbar/.logo/.page-head/.main/.pagefoot、.seg、.pref-row、.empty 基座、.spin/.lnk/.num/.serif。
判定依据：两端 base.css 这一段现在就已逐字相同（client base.css:9-115 与 server base.css:11-120），唯一差异是 S 端多出 daisyUI 过渡期的 visibility/pointer-events 守卫——属历史兼容残留，可在收尾时删除。
L2 语义层同名同义 · 各端薄壳
徽标 .pill、提示条 .notice 四语气、表单错误态 .f-err/.f-hint/.has-err、骨架屏原子 .sk、面板卡 .panel(+hoverable/hl/compact)、空态动作槽。类名和取值必须跨端一致；但 React/Vue 的组件壳不必对称（见 §四）。
L3 业务层允许分叉 · 只能重组不能造色
C端阅读工作台 book.css（结构树/密度）、设定视图三段式、基调选择器；S端落地营销页 landing.css（hero 字阶已登记例外）、控制台数据密表（keyline 掩码指纹）、认证页单列居中。
白名单纪律：可以改变「组合」与「密度」，但只能用 L1 已有令牌；新色相禁止，新字阶/圆角必须登记进词汇表。
色相登记簿（2026-08-28，theme-preferences）：默认 accent = teal（oklch(48% 0.11 170)，无 data-theme 属性时的基础令牌值）。用户可选主题集合经 :root[data-theme] 覆盖层表达（两端 @cross 段逐字同）：ink 玄墨 oklch(37% 0.01 250) · bamboo 竹青 oklch(60% 0.076 152) · rouge 胭脂 oklch(58% 0.11 8) · wisteria 紫藤 oklch(58% 0.084 296) · celadon 青瓷 oklch(65% 0.066 184)（strong 档 = L−6 同色相同 chroma；soft 由 color-mix 派生）。白名单单一事实源 = server/app/domain/identity/theme.py；增删改主题须双端同批 + 本登记簿同批。

3.2 提示条：统一名 .notice，显式四语气

S 端 .strip 与 C 端 .notice 是同一个对象的两个名字。取名取 C 端（更直白且已有调用），档位取 S 端（更完备）：统一为 .notice + 显式修饰类 info / ok / warn / err。语气词表全站收敛为这一个四元组——不再出现「success/danger」这套与 dot-ok/dot-warn/b.ok/toast.err 冲突的第二套措辞。

info 模型返回为空时将自动重试一次。
ok 激活码已绑定到当前设备。
warn 免费版每月 30 次生成额度已用去 24 次。
err 授权校验失败，请检查网络后重试。

迁移映射：.strip.ok → .notice.ok、.strip.err → .notice.err、.strip.info → .notice.info（S 端 6 文件）；C 端保留裸 .notice = warn 作为已登记的向后兼容缺省（存量两处调用不动），新代码一律写显式修饰类。此前 uikit 候选集里的 success/danger 语气词已同步改齐为 ok/err（2026-08-27，候选源码 Notice.tsx 与 CSS 段落均已更名）。

3.3 骨架屏：认 .sk 为原子，卡片骨架是它的组合

动画取值不同的本质是「谁向谁看齐」。裁决规则：当两端取值不同且都合规时，以受像素 parity 门禁约束的一端（C端）为准——改 C 要过原型与 design:check，改 S 不需要，所以永远向 C 收敛成本最低。故脉冲谷值定为 0.45、关键帧统一叫 sk-pulse；C 端 .card-skeleton .bar 改挂 .sk 类并删除本地 skeleton-pulse，S 端值从 0.55 调至 0.45。

3.4 新令牌 --on-accent：止住「拿 surface 当反白」的暗病

两端共有 8 处（.btn-primary、.btn-danger、.logo-mark、.toast 文字）写在 accent/深底上的文字都在用 color: var(--surface) 凑数——语义上那是「页面表面」不是「强调底上的文字」。一旦未来出现非白的强调底（如品牌深绿按钮 hover 态），这 8 处会一起错。这是一次性 5 分钟的修正：

:root { … --on-accent: oklch(100% 0 0); }     /* 两端 :root 各加一行 */
.btn-primary  { color: var(--on-accent); }     /* 替换 var(--surface) ×4 每端 */
.btn-danger   { color: var(--on-accent); }
.logo-mark    { color: var(--on-accent); }
.toast        { color: var(--on-accent); }

React 与 Vue 无法直接共用 TSX/Vue 组件代码——所以「组件一致」的正确含义是类名契约一致，壳是各端自己的实现细节。值得注意的是两端已经各自形成了薄壳传统，且风格取舍相反但都合理，不要强行拉平：

六、防再漂移机制（本方案的核心交付）

M1 已落地（2026-08-28 #218）：两端 base.css 已打 @cross-begin/@cross-end 标记，scripts/design-cross.mjs 已建零差异基线并挂两端 design:cross（负向验证 exit 1）。注意：实际入段范围 = 令牌+基础类+pill 家族+sk+表单错误态+toast.warn；notice 基座/panel/empty-slot 三族按上文缓收编裁定暂在各自本地段。M2/M3 未动。

M1 · design:cross：把「必须逐字相同的段落」变成机器断言

在两端 base.css 中用标记注释显式圈出 L1+L2 共享区间，仓库根放一个比对脚本，任何一端单独改动都会立刻红：

// 规范化空白后 strict 相等；不等 → 打印第一处分歧行号并以退出码 1 结束。
export function crossSegments(css) { … }
const [c, s] = await Promise.all([read(CLIENT_BASE), read(SERVER_BASE)]);
if (norm(crossSegments(c)) !== norm(crossSegments(s))) { diff(); process.exit(1); }

M2 · 图标公共键断言

并入同一脚本：抽取两端注册表的键集合，公共键逐一比对 d 属性字符串；发现同名不同形立即报错。31 个公共键从此不可能悄悄分叉。

M4 · OpenSpec 范围升格为「全端」

  • openspec/config.yaml context 增加 S 端一段：栈（Vue 3 + Tailwind 4 仅布局）、设计事实源位置、以及「S 端用户可见改动同样走 Design Impact 与 design:lint」；
