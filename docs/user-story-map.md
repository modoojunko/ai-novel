# 用户故事地图 — AI Novel（爱小说）

> **版本**: 3.0 | **最后更新**: 2026-07-24
>
> 以**用户路径**描述用户如何一步步使用系统。覆盖 C端（本地写作客户端）和 S端（License 管理平台）。

# 核心设计原则（2026-07-24 修正）

**登录和 License 的关系：**

```
注册 ──→ 登录 ──→ Dashboard
                    ├── 有有效 License → 正常使用
                    └── 无 License / 已过期 → 提示激活/续费，可操作
```

**关键规则：**
- **登录不校验 License** — 即使用户 License 过期，也必须能登录
- **License 只控制功能权限** — 不影响登录、查看状态、输入激活码
- **用户必须能登录才能消费新卡号** — 过期用户登录 → 看到过期提示 → 输入新激活码 → 恢复使用

**6 阶段工作流与门控机制：**

```
init ─→ settings ─→ outline ─→ prompt ─→ write ─→ archive
  ↑ gate: 至少5个世界设定字段
                       ↑ gate: 章纲完整性校验
                                     ←──── backward: 下一章回到 outline
```

**门控规则：**
- 每个 transitions 都有验证门（gate），验证失败返回 400 + 缺失项列表
- 唯一允许的回退：write → outline（用户开始下一章时）

# C端 — 创作者旅程

## 主路径：完整创作流程

```
落地页 ──→ 注册 ──→ 登录/SSO ──→ API Key配置 ──→ Dashboard ──→ 设定 ──→ 大纲 ──→ 提示词 ──→ 写作 ──→ 归档
                    ↑                                          ↑ gate       ↑ gate     ↑ gate      ↑
                    └── 已有账号 ──────────────── 直接登录 ────┘             ←─── 下一章 ───┘
                                                                                (write→outline)
```

## 分支路径

```
续费路径： Dashboard（过期提示） → 输入激活码 → License 恢复
设定期 AI路径： 设定页 → 选中字段 → AI 建议 → 接受/换一个 → 确认 → 保存
项目外推演： 故事推演 → 初始化场景 → 设置种子 → 执行回合 → 调整个体 → 停止 + 摘要
重置密码： 重置密码页 → 输入用户名 → 密保答案 + 新密码 → 成功 → 去登录
```

**Story 1.5**: 作为已有账号用户，登录状态点击"我的作品"直接进入 Dashboard。

### 第5步：小说设定（Phase 1-2）→

**用户画像**：新建项目后，在开始写作前完成世界、风格、角色等设定。

**门控前提**：init → settings 无强制门控（新建项目自动进入 settings）。

**设定列表（6 种类型）**：

| 类型 | Tab | AI 辅助 | 门控要求 |
|------|-----|---------|----------|
| 世界设定 | 地理 / 政治 / 规则 | 支持逐字段生成 | 至少 5 个字段非空 |
| 写作风格 | 叙事身份 / 核心原则 / 常见错误 / 描写技法 | 支持逐字段生成 | role（叙事身份）必填 |
| 反AI规则 | 疲劳词 / 句式规则 / 改写算法 | 无（禁止 AI） | 无强制 |
| 伏笔面板 | 活跃伏笔 / 已收束 / 废弃 | 支持生成 | 至少 3 个活跃伏笔 |
| 角色管理 | 基本信息 / 认知模型 / 扩展信息 | 支持逐字段生成 | 无强制 |
| AI 模型 | 模型选择 / 参数配置 | 无 | 无强制 |

**Story 5.1**: 作为用户，进入项目后自动进入设定 Tab，左侧 6 个设定项按 Lucide 图标排列。

**Story 5.2**: 作为用户，世界设定有 3 个 Tab（地理、政治、规则），每个 Tab 下有多个填空字段和文本域。

**Story 5.3**: 作为用户，写作风格有 4 个 Tab（叙事身份、核心原则、常见错误、描写技法），支持列表编辑器（添加/删除项）。

**Story 5.4**: 作为用户，反AI规则有 3 个 Tab（疲劳词分类、句式规则、改写算法），纯粹手动配置，没有任何 AI 按钮。

**Story 5.5**: 作为用户，伏笔面板有 3 个 Tab（活跃伏笔、已收束、废弃），支持添加/编辑/删除伏笔行（描述、引入位置、类型、优先级）。

**Story 5.6**: 作为用户，角色管理支持创建角色（填写名字+选择主角/反派/配角），点击角色进入详情面（3 Tab：基本信息/认知模型/扩展信息），支持删除角色（确认弹窗+二次验证）。

**Story 5.7**: 作为用户，每个设定的可 AI 生成字段上有"AI 帮我填"按钮，点击打开 AI 建议弹窗，显示生成内容，支持"接受这个"填入字段或"换一个"重新生成。

**Story 5.8**: 作为用户，点击"AI 一键生成全部设定"按钮，打开进度弹窗，依次生成所有 5 种设定（反AI 除外），完成后自动填充。

**Story 5.9**: 作为用户，每个设定确认后可点击"标记完成"切换为"已完成"状态。

**Story 5.10**: 作为用户，确认所有 6 种设定后，正文 Tab 的门控开放——不再显示"设定尚未全部完成"，而是显示"开始写你的第一部小说"。

**Story 5.11**: 作为用户，保存的设定内容会持久化存储，刷新页面后可见。

### 第6步：大纲规划（Phase 3）→

**用户画像**：完成设定后，开始创建卷和章，规划章节内容。

**门控前提**：settings → outline gate 要求世界设定至少 5 个字段、写作风格 role 已填、至少 3 个伏笔。

**Story 6.1**: 作为用户，完成设定后点击"正文"Tab，门控通过后显示"开始写你的第一部小说"空状态，点击"创建第一卷"创建第一册。

**Story 6.2**: 作为用户，创建卷时填写"卷名"和"卷纲"（文本域），卷纲概述本卷情节走向。

**Story 6.3**: 作为用户，创建卷后左侧卷章树展开，显示卷名和章节数量徽标（如"1章"）。

**Story 6.4**: 作为用户，在卷下点击"添加章节"创建章节，默认命名为"第1章"等递增名称。

**Story 6.5**: 作为用户，点击章节在右侧打开章节编辑器，包含 5 个 Tab：

| Tab | 内容 | 功能 |
|-----|------|------|
| 章纲 | summary + key_points + characters + location + time + narrative_pov | 自动保存（3s 防抖） |
| 备注 | memo 对象：current_task, reader_expectation, required_changes, prohibitions 等 | 自动保存 |
| 分段 | segments 列表：每段意图/字数/概要 | 增删改 |
| 视角 | 调用 AI 将上帝视角章纲转换为沉浸式 POV 引导 | AI 生成，写入 chapter |
| 情绪 | emotional_design: primary_mood + 强度 + 节奏 | 表单编辑 |

**Story 6.6**: 作为用户，编辑章纲文本域会触发自动保存（3 秒防抖），刷新页面内容不丢失。

**Story 6.7**: 作为用户，正文文本域支持 markdown 书写，预览模式渲染 markdown。

**Story 6.8**: 作为用户，点击"专注模式"隐藏侧边栏和额外 UI 元素，专注于写作。

**Story 6.9**: 作为用户，章节状态支持下拉切换（outline / writing / editing / proofreading / archived）。

**Story 6.10**: 作为用户，章纲完成后点击"确认章纲"触发门控校验，校验失败时显示缺失项列表。

**Story 6.11**: 作为用户，门控通过后状态变为 confirmed，可进入下一阶段（提示词生成）。

### 第7步：提示词生成与预览（Phase 4）→

**用户画像**：完成章纲后，生成 AI 提示词，预览和编辑后用于正式写作。

**门控前提**：outline → prompt gate 要求章纲通过校验（current_task、reader_expectation、required_changes、emotional_design.primary_mood、segments 均非空）。

**Story 7.1**: 作为用户，确认章纲后点击"生成提示词"，系统将设定+章纲组装为每段的完整提示词文件（.md）。

**Story 7.2**: 作为用户，左侧卷章树中对应章节显示提示词已生成的标记。

**Story 7.3**: 作为用户，可跨章浏览所有已生成的提示词列表（按章节分组的文件名）。

**Story 7.4**: 作为用户，点击提示词文件名可预览完整的提示词内容。

**Story 7.5**: 作为用户，可编辑提示词内容（文本域），修改后保存覆盖。

**Story 7.6**: 作为用户，如对提示词不满意，可重新生成（覆盖已有提示词）。

**Story 7.7**: 作为用户，提示词完成后切换到写作 Tab，进入正文编辑器开始 AI 写作。

---

### 第8步：正文写作（Phase 5）→

**用户画像**：提示词就绪后，进入正文编辑器进行 AI 辅助写作和手动编辑。

**门控前提**：prompt → write gate 要求该章节的提示词文件已存在（至少 1 个 segment prompt）。

**Story 8.1**: 作为用户，正文编辑器加载后显示已有 prose 内容（如有），左侧卷章树可切换章节。

**Story 8.2**: 作为用户，点击某个 segment 的"AI 写作"按钮，建立 SSE 流式连接，逐 Token 显示生成内容。

**Story 8.3**: 作为用户，SSE 流式输出过程中可看到逐字渲染、实时更新页面内容。

**Story 8.4**: 作为用户，写作过程中自动保存版本快照（每次 prose 或 outline 变化时）。

**Story 8.5**: 作为用户，编辑器支持 markdown 语法编辑和预览切换。

**Story 8.6**: 作为用户，字数统计实时更新（tabular-nums 显示）。

**Story 8.7**: 作为用户，专注模式可隐藏侧边栏，退出专注模式恢复完整布局。

**辅助写作功能：**

**Story 8.8（续写）**: 作为用户，将光标定位在正文任意位置，点击"续写"按钮，AI 根据前文（光标前 1500 字）+ 设定/风格/角色状态生成后续文字，SSE 流式输出。生成后自动保存合并。
- 输入：cursor_position（插入点）+ 已写正文
- 输出：流式 chunk → 合并到 prose → 生成版本快照
- 上下文：写作风格、反AI 规则、角色快照、活跃伏笔

**Story 8.9（润色）**: 作为用户，选中正文中的一段文字，点击"润色"按钮，AI 在保持原意和风格的前提下优化语言表达。
- 输入：selected_text + surrounding_context
- 输出：返回润色后的完整文本（非流式）
- 模型：默认 haiku，可覆盖

**Story 8.10（扩写）**: 作为用户，选中正文中的一段文字，点击"扩写"按钮，AI 在保持风格的前提下展开细节描写、丰富场景。
- 输入：selected_text + surrounding_context
- 输出：返回扩写后的完整文本（非流式）
- 模型：默认 haiku，可覆盖

**版本管理：**

**Story 8.11**: 作为用户，每次 prose 或章纲内容变化时，系统自动创建版本快照（YAML 元数据 + 快照）。

**Story 8.12**: 作为用户，在编辑器中点击"历史版本"按钮，查看当前章节所有版本列表（按时间倒序）。

**Story 8.13（行级 diff）**: 作为用户，选择任意两个版本，系统显示行级差异对比（新增行/删除行/修改行高亮）。

**Story 8.14（词级 diff）**: 作为用户，在行级 diff 基础上，进一步查看词级变更（单词/词组的高亮对比）。

**Story 8.15**: 作为用户，在 diff 查看中可"恢复到历史版本"（将当前 prose 回滚到指定版本快照）。

### 第9步：归档与回顾（Phase 6）→

**用户画像**：章节写作完成，质量检测通过后，将章节存档。

**门控前提**：write → archive gate 要求 prose 长度 >= 100 字。

**Story 9.1**: 作为用户，正文编辑器中的"归档"按钮始终可见，但仅 prose >= 100 字时 API 才允许归档。

**Story 9.2**: 作为用户，点击"归档"触发归档 API：
- 当前 prose 写入 archives/{chapter_ref}-{timestamp}.md
- 项目 total_archives +1
- 阶段推进到 archive
- 显示"归档成功"提示

**Story 9.3**: 作为已归档用户，我可以在归档列表中浏览所有已归档章节（按创建时间倒序）。

**Story 9.4**: 作为已归档用户，点击归档条目可在阅读器中查看 markdown 渲染内容。

**Story 9.5**: 作为已归档用户，归档阅读器支持平滑阅读体验（类似电子书阅读器样式）。

**Story 9.6（下一章）**: 作为用户，归档后可以选择"开始下一章"——触发 write → outline 回退，创建新章节 chapter_ref 递增。

**Story 9.7（导出 v2）**: 作为用户，未来可将所有归档章节导出为完整小说文件 ePub / PDF / TXT。（v2 功能，暂未实现）

## 分支路径

### 路径A：续费（License 过期用户）

**Story A.1**: 作为 License 已过期的用户，我仍可正常登录（登录不校验 License），进入 Dashboard。

**Story A.2**: 作为 License 已过期用户，Dashboard 显示"AI 试用已到期"红色警告 + "输入激活码续费"入口。

**Story A.3**: 作为 License 过期用户，输入新激活码后调用续费 API，到期日期自动叠加，License 恢复后功能恢复正常。

### 路径B：项目外推演（剧情推演）

独立于 6 阶段工作流的辅助工具，在项目外运行。

**Story B.1**: 作为用户，以项目为起点初始化推演会话：系统加载角色、场景、当前状态（从 world-setting / character-setting 读取）。

**Story B.2**: 作为用户，设置推演种子（trigger seed），描述即将发生的事件或情境。

**Story B.3**: 作为用户，执行推演回合：AI 驱动角色根据设定做出决策（基于性格/知识/情绪/紧迫感等因素），产生行动和结果。

**Story B.4**: 作为用户，每个回合后查看每个角色的感知日志（see/hear/sense/understanding）、内心独白、实际行动和影响。

**Story B.5**: 作为用户，可在任意回合调整角色状态（位置/体力/情绪/紧迫感/知识）或舞台设定（场景/时间/天气）。

**Story B.6**: 作为用户，可回退到历史回合（rewind），分支探索不同剧情走向。

**Story B.7**: 作为用户，结束推演后获得完整推演摘要（总回合数、种子、事件记录、角色变更历史）。

### 路径C：密码重置

# 工作流门控矩阵

完整记录每个阶段转换的门控条件，用于开发参考和测试用例设计。

| 转换 | 门控条件 | 通过后阶段 | 失败返回 |
|------|---------|-----------|----------|
| init → settings | 无门控（自动推入） | settings | — |
| settings → outline | 世界设定 ≥5 字段已填 + 写作风格 role 非空 + 伏笔 ≥3 | outline | 400 + 缺失项列表 |
| outline → prompt | chapter 门控：current_task + reader_expectation + required_changes + emotional_design.primary_mood + segments 均非空 | prompt | 400 + 缺失项列表 |
| prompt → write | 该章节至少有一个 prompt 文件已生成 | write | "Prompt not found" |
| write → archive | prose 长度 ≥ 100 字 | archive | "Text too short to archive" |
| archive → outline | 无门控（可自由创建下一章） | — | — |

# 版本快照与差异对比机制

**触发条件**：每次 `save_chapter` 调用时，检测旧 prose 和新 prose 是否不同，或旧 outline summary 和新 outline summary 是否不同。

**快照存储**：`versions/{chapter_ref}/v{timestamp}.yaml`，包含：
- version: 时间戳 v{t}
- chapter_ref, created_at, comment
- snapshot: { prose, outline, status }

**Story V1**: 作为用户，每次保存章节时自动创建版本快照，无需手动操作。

**Story V2**: 作为用户，在历史版本面板中查看按时间倒序排列的版本列表。

**Story V3**: 作为用户，选择两个版本进行差异对比，系统渲染行级 diff（左侧旧版本 / 右侧新版本，新增行绿色、删除行红色背景）。

**Story V4**: 作为用户，在行级 diff 基础上进一步展开到词级对比（高亮行内新增/删除/修改的词）。

**Story V5**: 作为用户，在 diff 查看器中点击"恢复到此版本"，将当前 prose 替换为选中版本的快照内容。
