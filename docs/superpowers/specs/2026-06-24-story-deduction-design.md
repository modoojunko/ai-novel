# 剧情推演 — 设计文档

## 概述

多角色回合制剧情推演系统。每个角色是独立 agent，具有主观认知 6 层模型和独立的视野边界。作者提供触发种子，系统模拟多轮角色独立决策，涌现出剧情走向。

核心灵感来自 MiroFish 的多 agent 涌现式推演，但针对小说场景做了适配——轻量化、回合制、全知视角展示。

## 用户流程

```
作者在编辑器点击「🔮 剧情推演」
       ↓
① 自动初始化
  ├── 读取项目舞台：world-setting + 当前章节场景
  ├── 读取参与角色：character-setting/*.yaml（认知6层）
  └── 读取当前剧情状态：章纲 + 前情摘要
       ↓
② AI 检查完整性 → 缺的引导作者补充
  如：「当前章节未指定出场角色，请选择」
       ↓
③ 展示初始化结果 → 作者确认
  舞台：丹霞峡谷·白天
  角色：A、B、猎人×5
       ↓
④ 作者输入触发种子
  「B 朝 A 射了一箭」
       ↓
⑤ 第 1 回合推演
  ├── 为每个角色计算视野
  ├── 每个角色独立决策（认知6层推导）
  └── 动作落地 → 舞台更新
       ↓
⑥ 展示第 1 回合结果
  ├── 舞台地图（角色位置+状态）
  ├── 角色状态列表
  └── 事件墙
       ↓
⑦ 作者选择：
  ├── 继续下一回合
  ├── 停止，输出剧情走向
  └── 调整角色状态再继续
       ↓
⑧ 反复直到作者满意
       ↓
⑨ 保存推演记录，可采纳作为章纲
```

## 回合制决策管线（严格协议）

### 核心约束

```
1. 每一轮推演由 3 个严格的阶段组成，不允许跳步，不允许合并
2. 每个角色每一轮只能做 1 次决策（1 次 LLM 调用）
3. 每个角色只知道「ta 该知道的」，不知道全局信息
4. LLM 不允许替角色做出「超出认知」的决策
5. 所有角色决策完成后，才统一进入下一轮
```

### Step 0 — 初始化（仅第 1 轮）

```
AI 解析触发种子 + 当前舞台 → 输出结构化的初始状态：

StageState:
  terrain: "丹霞峡谷·白天"
  events: ["B朝A射了一箭"]       # 公开事件池
  characters:
    - id: A
      position: "峡谷中段"
      status: "体力透支·缺水"
      knowledge: ["被朝廷悬赏"]   # ta知道的事
      urgency: "找水·活下去"
    - id: B
      position: "前方50米山谷"
      status: "体力充沛"
      knowledge: ["A从西边来了", "目标是悬赏犯"]
      urgency: "完成赏金任务"
    - id: 猎人1-5
      position: "前方100米山上"
      status: "体力充沛·埋伏中"
      knowledge: ["A从西边来了", "彼此是队友"]
      urgency: "伏击成功"

 视野定义（初始）:
    A: { vision: "峡谷底部，视线受限", hearing: "正常", notes: "看不到前方有埋伏" }
    B: { vision: "山谷开阔，能看到A", hearing: "正常", notes: "看不到山上的猎人" }
    猎人1-5: { vision: "高处，能看到A和B", hearing: "受距离衰减", notes: "能看到全场" }
```

### Step 1 — 感收集（每轮开始）

```
输入：当前 StageState
过程：系统基于每个角色的五感范围 + 当前位置，计算「ta 本回合能收集到什么信息」

每个角色收集的信息：
  ① 视觉：看到什么（方向/距离/遮挡物）
  ② 听觉：听到什么（距离/环境干扰）
  ③ 嗅觉/触觉/第六感：闻到什么、感觉到什么
  ④ 环境信息：天气、时间、地形对自己状态的影响

输出示例（给 A 的感知信息）：
  SensoryInput:
    see: "峡谷两侧岩壁高耸，前方有块巨岩，一支箭从西侧飞来钉在岩壁上"
    hear: "山上有石头滚落的声音，风声"
    smell: "干燥的尘土味"
    feel: "体力透支，口干舌燥"
    environment: "白天，起风了，峡谷中光线充足但视线受岩壁遮挡"

⚠️ 系统层面保证：感知信息是硬边界
   LLM 角色 prompt 中不包含感知范围之外的任何信息
   角色不知道的事 = prompt 里不会出现
```

### Step 2 — 角色决策（独立 LLM 调用 × N）

```
每个角色一次独立的 LLM 调用，严格遵守：

输入（仅包含以下信息）：
  ① 角色的认知 6 层（从 character-setting 加载）
  ② Step 1 收集到的角色感知 SensoryInput
  ③ 当前的紧急事项
  ④ 角色已有的 knowledge（历史累积）

LLM 的输出必须是严格结构化的 JSON，记录完整的决策链路：

DecisionLog:
  ── 感知层 ──
  see: "看到了什么（基于视野分配的结果）"
  hear: "听到了什么"
  sense: "其他感知（嗅觉/直觉/第六感…）"

  ── 认知层 ──
  understanding: "基于我的世界观+自我定位，我如何理解现在的局面"
  values_checked: "我确认了什么能做、什么不能做"
  ability_assessment: "我评估了自己有什么手段可用"
  urgency: "当前对我来说最紧急的事"

  ── 情绪层 ──
  emotion: "我现在的情绪状态"

  ── 决策层 ──
  decision_process: "经过以上判断，我决定怎么做"
  action:
    type: "移动" | "攻击" | "喊话" | "隐藏" | "观察" | …
    target: "可选"
    description: "具体动作描述"

  ── 结果层 ──
  inner_monologue: "角色的内心独白（第一人称）"
  action_impact: "这一行动可能带来的后果（角色自己的预判）"

⚠️ 约束：
   1. LLM 不能替角色知道「ta不该知道的信息」
   2. LLM 不能替其他角色做决策
   3. 动作必须是在角色当前能力范围内
   4. inner_monologue 必须100%角色视角，不能用全知叙事
   5. 每个层都必须填写，不允许跳过

⚠️ 约束：
   1. LLM 不能替角色知道「ta不该知道的信息」
   2. LLM 不能替其他角色做决策
   3. 动作必须是在角色当前能力范围内
   4. inner_monologue 必须100%角色视角，不能用全知叙事
```

### Step 3 — 结果汇总 + 舞台更新（纯系统计算）

```
输入：本轮所有角色的 Decision 列表

过程（不上 LLM，纯逻辑处理）：
  ① 整理所有角色的动作 → 写入本轮事件墙
  ② 计算动作结果
     - 射箭 → 命中/未命中（基于双方状态、距离、环境）
     - 移动 → 新位置
     - 喊话 → 谁听到了
     - 隐蔽 → 成功/失败
  ③ 更新角色状态（位置、体力、情绪）
  ④ 更新主观关系变化
  ⑤ 更新 StageState

输出：
  StageState（更新后的舞台）
  RoundSummary:
    events:
      - round: 1
        timestamp: "..."
        items:
          - actor: B
            action: "射箭"
            target: A
            result: "未命中（A翻滚到巨岩后）"
            visibility: 公开
          - actor: A
            action: "翻滚到巨岩后"
            target: null
            result: "获得掩体"
            visibility: 公开
          - actor: 猎人1
            action: "打手势"
            target: [猎人2,3,4,5]
            result: "开始包抄"
            visibility: 仅猎人间
          ...
    relationship_changes:
      - from: A, to: B, change: "确认被袭击", strength_delta: -10
```

### 回合流程总览

```
一轮开始
  │
  ├── Step 1: 感收集（系统计算，非 LLM）
  │   每个角色收到 ta 本回合的五感输入
  │
  ├── Step 2: 角色决策（N 次独立 LLM 调用）
  │   每个角色基于视野 + 认知6层 → 输出动作
  │   严格隔离，角色之间不知道彼此决策
  │
  ├── Step 3: 动作汇总 + 舞台更新（纯系统计算）
  │   收集所有决策 → 更新舞台状态 → 写入事件墙
  │
  ├── Step 4: 作者调整（可选，人肉操作）
  │   作者可修改角色状态/舞台/关系 → 调整后的状态继续
  │
  └── 一轮结束 → 展示给作者
```



### Step 4 — 作者调整（可选）

```
输入：第 N 轮结果（StageState + CharacterState + RoundSummary）

作者作为全知者，可以调整以下内容：
  ① 角色状态：体力、位置、情绪、是否受伤、是否死亡
  ② 舞台状态：环境变化、新增事件
  ③ 关系变化：A 对 B 的看法改变
  ④ 注入新信息：某个角色「意外发现」了原本不知道的事

调整后 → StageState_N'（调整后的版本）
         → 以这个版本为输入，继续第 N+1 轮

调整方式（前端 UI）：
  ┌──────────────────────────────────┐
  │  第 1 回合结束                    │
  ├──────────────────────────────────┤
  │  [继续推演] [停止] [✎ 调整]       │
  └──────────────────────────────────┘
          ↓ 点击 [✎ 调整]
  ┌──────────────────────────────────┐
  │  选择要调整的对象                  │
  │  ├─ A（状态/位置/知识）           │
  │  ├─ B（状态/位置/知识）           │
  │  ├─ 舞台（环境/事件）             │
  │  └─ 关系（A→B 的认知）            │
  │                                   │
  │  调整内容（自由文本）：             │
  │  ┌───────────────────────────┐   │
  │  │ A 中箭了，左肩受伤，体力   │   │
  │  │ 从 40% 降到 15%           │   │
  │  └───────────────────────────┘   │
  │  [应用调整]                      │
  └──────────────────────────────────┘
  调整后 → 返回展示 → 继续推演
```

⚠️ 调整不是必要的：作者可以不调整直接继续，推演的效力来自角色独立决策的涌现结果。
调整是一种「作者干预」——当 AI 的推演方向偏离了作者对角色的理解时使用。

## 领域对象

### Stage（舞台）

推演过程中的共享状态：

```
Stage
  ├── terrain: 地形环境描述
  ├── time: 当前时间（推演内部时间线）
  ├── weather: 环境条件（影响感知范围）
  ├── characters: 角色位置和状态（引用）
  ├── event_pool: 已发生的公开事件列表
  └── round: 当前回合号
```

### Character（角色 · 聚合根）

参与推演的角色，数据来自 `character-setting/{name}.yaml` + 运行时状态：

```
Character
  ├── name / role / appearance / speech（基础属性）
  │
  ├── cognition_6layers（认知6层，从角色设定加载）
  │   ├── world_view    — 对世界运作的信念
  │   ├── self_image    — 如何看待自己
  │   ├── values        — 行为边界
  │   ├── abilities     — 能力上限
  │   ├── skills        — 习得技能
  │   └── environment   — 背景 + 当前处境（含主观关系认知）
  │
  ├── perception（感知能力 · 推演前定义）
  │   ├── vision: 视觉范围（方向/距离/遮挡）
  │   ├── hearing: 听觉范围（距离/环境干扰）
  │   └── special: 特殊直觉（如老兵第六感）
  │
  ├── runtime_state（运行时状态）
  │   ├── position: 当前位置
  │   ├── stamina: 体力
  │   ├── emotion: 情绪状态
  │   ├── urgency: 当前紧急事项
  │   └── knowledge: ta知道的信息集合
  │
  └── relationships（主观关系认知 · 扩展预留）
       ├── A→B: { type, strength, evolution[] }
       └── A→猎人1: { type, strength, evolution[] }
       每回合结束后更新
```

### Round（回合）

```
Round
  ├── round_number: 回合号
  ├── decisions: Decision[]
  ├── stage_snapshot: 此回合开始前的舞台状态
  └── events: 此回合产生的事件
```

### Decision（决策）

```
Decision
  ├── character_ref: 角色引用
  ├── sensory_input: 此角色本回合收集到的五感信息（原始输入）
  │
  ├── decision_log（完整决策链路记录）
  │   ├── see / hear / sense（感知层）
  │   ├── understanding（认知层：世界观+自我定位）
  │   ├── values_checked（认知层：价值观边界）
  │   ├── ability_assessment（认知层：能力+技能）
  │   ├── emotion（情绪层）
  │   ├── urgency（当前紧急事项）
  │   ├── decision_process（决策层：以上各层综合后的推导）
  │   ├── action（决策层：具体动作）
  │   ├── inner_monologue（内心独白，第一人称）
  │   └── action_impact（角色预判的后果）
  │
  └── timestamp: 决策时间戳
```

### Action（动作）

```
Action
  ├── type: 移动/攻击/喊话/隐藏/观察/拾取/使用道具…
  ├── target: 目标（可选）
  ├── is_public: 是否公开
  ├── description: 动作描述
  └── inner_monologue: 角色内心独白
```

## 推演起始条件

推演开始前需要：

```
✅ 必须就绪                    → 从项目读取
  ├── world-setting.yaml      → 舞台基础
  ├── character-setting/*.yaml → 角色认知6层
  ├── 当前章节 chapter.yaml   → 当前剧情状态
  └── 前几章摘要               → 前情提要

⏳ 需要补充（AI 引导作者填）
  ├── 出场角色选择             → 哪些角色参与本场推演
  ├── 场景位置                 → 发生在哪（如未指定）
  └── 触发种子                 → 第一推动力

完整性检查在 `POST /api/story/init` 时自动执行——AI 读取现有数据后，返回 `missing: [...]` 列表，前端逐项引导作者补充。
```

## 结束条件

由作者手动控制：
- 每回合结束后查看结果
- 选择继续、停止、或调整
- 达到 N 回合时建议停止（推演疲劳阈值）

## 关系追踪（扩展预留）

```
Character.relationships:
  target_character_id: {
    type: "enemy" | "friend" | "neutral" | "unknown" | …,
    strength: 0-100,
    evolution: [
      { round: 0, type: "enemy", strength: 80, trigger: "初始设定" },
      { round: 1, type: "enemy", strength: 75, trigger: "射箭未中" }
    ]
  }
```

- 初始值从角色设定的 `relationships` 字段解析
- 每回合结束后 AI 判断关系是否有变化
- 推演结束后可写入角色文件永久保存
- 关系变化作为「环境」层的一部分输入下一回合
