# 设计：主线卡「基调」改为「问句 + 带解释的选项」

## 为什么之前的设计不行

两版都败在同一件事上：**一排裸按钮，没有在回答任何看得见的问题。**

- v1（已上线）：未定/悲/喜/开放/待定 五个裸按钮 —— 「未定」「待定」撞车，看不懂
- v2（上一稿）：删到 悲/喜/开放 三个裸按钮 —— 词是清楚了，但用户仍然不知道：
  这是在选什么？选了会怎样？能不能不选？点了怎么取消？

按钮天生是「执行动作」的东西（保存、删除、添加），而这里其实是**回答一个选择题**。用选择题的方式出题，人一下就懂。

## 改后长这样

```
结局想法
┌──────────────────────────────────────────────┐
│ 故事读到最后，你想要哪种感觉？（可不选）      │
│                                              │
│  ○ 悲——主角没得到想要的，或付出惨痛代价      │
│  ○ 喜——目标达成，苦尽甘来                    │
│  ○ 开放——结局留白，答案交给读者              │
│  ○ 自己写 ▷（点开后一个填空，例：先悲后喜）  │
└──────────────────────────────────────────────┘
```

- 第一行是**问句**：人先看到问题，再看选项，不需要猜
- 每个选项 = 一个词 + 一句人话解释，不再是裸按钮
- 「可不选」写在问句里，明说这件事不强制
- 再点一次已选中的选项 = 取消选择（回到没选）
- 没选时不显示任何占位词、不显示提示灰字——问句加「可不选」已经把话说完了
- 第四项「自己写」：作家自定义——点选后出现一个填空框，想写什么写什么
  （例：先悲后喜 / 团圆但留遗憾）。三个预设仍可随时切回；再点「自己写」取消并清空填空

## 向导联动（不变的部分）

- 第 2 步「没想好，先跳过」：不动这个字段（沿用上一稿决定，不再偷偷写「待定」）
- AI 聊结局时仍把已选基调喂给提示词；没选就不喂
- 可续步（next_step）只看「基调是否有值」，逻辑不变

## 自定义基调（自己写）

- 存储仍是 tone 一个自由字符串：预设三个值之外的非空文本即「自己写」态
- 点「自己写」→ 展开填空框，写什么存什么；清空填空 = 等于没选
- 三个预设与「自己写」互斥单选：点预设清掉自定义文本，点「自己写」取消预设
- 向导/AI 提示词不改：tone 是什么就喂什么，自定义文本照常生效

## 旧数据兼容

- 存量 tone="悲"/"喜"/"开放"：直接映射到对应选项
- 存量其他任意非空文本（含以前手滑存的奇怪值）：按「自己写」态显示，文本进填空框
- 存量 tone="待定"：按没选显示，保存即清空
- 后端零改动（字段本来就是自由字符串，前端归一化）

## 实现要点

- StoryArcForm：基调区从 seg 按钮组改为单选列表（radio 语义，键盘可用），选项文案 `词——解释` 一行
- 「自己写」项选中态判断 = tone 非空且不等于三个预设值
- design-lint：沿用现有 btn/seg 词汇，radio 列表用既有 `.field`/label 体系，无新词
- 测试：vitest 改选项断言 + 新增「再点取消」「旧数据待定显示为没选」两用例；e2e 无涉及基调断言（已确认）

## 风险

小。仍是 StoryArcForm 单文件为主，交互从按钮组换成 radio 组，不碰后端与存储。
