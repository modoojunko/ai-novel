# Proposal: account-deletion（账号自助注销）

## Why

《用户服务协议》§三.4 与《隐私政策》均已向用户承诺注销权（个保法第 47 条要求的法定义务），但产品当前**没有任何注销入口**——用户只能走客服邮箱人工办理、15 个工作日。这既是合规缺口（必须提供便捷的注销途径），也是体验欠账（无邮箱无手机号的账号体系下，邮件通道本就不可达）。本次立项把注销做成 S 端自助功能，人工邮箱通道降级为兜底。

## What Changes

- **新增 S 端自助注销流程**：S 端控制台提供「注销账号」入口，站内完成确认（账号无邮箱无手机号，不允许站外触达）：
  - 后果告知（本地作品不受影响、未消耗权益处置、交易记录依法留存、15 天撤销期）→ 输入密码二次确认 → 进入 15 天撤销期 → 到期自动执行注销。
  - 撤销期内登录时显著提示可撤销，撤销即恢复账号。
- **注销执行（S 端 API + 数据处置）**：
  - `users` 行去标识化：抹除 username/密码哈希等身份字段，行本身保留（交易记录外键完整性依赖它）；
  - `device_grants` / `device_registry` 绑定关系清理；
  - `codes` 套餐台账中未消耗权益按处置决策作废（已回收/退款冻结行不动）；
  - **交易记录（orders/trade_events/refunds）依法留存约 10 年（P2 决策）**：保留金额与时间，抹除与自然人身份的直接关联；openid 支付留存认证（P1 决策）用于争议举证，不属于可识别日常身份的展示信息；
  - 注销执行后该用户全部会话令牌失效（JWT 无法再通过认证）。
- **注销前资产处置（推荐方案：引导退款为主、显式放弃兜底）**：存在待激活/排队中/消耗中套餐时，注销向导先引导用户走**既有订单页退款流程**（复用《退款政策》既有折算与原路退回链路，注销功能不新造任何资金规则）；用户也可显式勾选「放弃未消耗权益」继续注销。理由：① 协议 §三.4 承诺未消耗套餐按《退款政策》办理退款，不引导即合规暴露；② 资金动作留在既有退款链路，注销 API 与资金流解耦，在无多表事务的 pg_http 环境下把退款混进注销是最高风险路径；③ 退款原路退回不依赖账号存活，注销不影响在途退款到账。
- **C 端登录态失效处理**：注销执行后，桌面客户端持有的 JWT（config.json）在下次请求时失效，客户端清理本地凭据并回到登录页；本地 SQLite 中的作品内容**原样保留**（服务端从未存储作品，注销不涉及任何作品数据）。
- **法律协议联动（2026-08-29 更新：协议侧已提前完成）**：《用户服务协议》已先行写入完整注销条款组（§三.4–7：自助入口+客服兜底双通道、15 天撤销期与到期自动执行、六项后果告知、效力存续），《隐私政策》口径已同步；实施期仅剩核对任务（tasks 8.1–8.3）。
- **范围外（Non-Goals）**：不实现账号数据导出/查阅报告；不改动退款政策与退款流程本身；不涉及作品内容的任何服务端处理（本站不存作品）；不做注销后 username 短期复用（推荐永久封存，见 design D5）；管理面（ADMIN_TOKEN API）不支持代办注销。

## Capabilities

### New Capabilities

- `account-deletion`: 账号自助注销能力——S 端注销申请/撤销/到期执行的完整行为（含前置资产校验、站内确认、去标识化数据处置、会话失效），沿仓库既有扁平 capability 命名习惯。

### Modified Capabilities

- `frontend-auth-heal`: 新增需求——C 端收到认证失效（含注销导致的失效）时，清理本地登录态并回到登录页的既有一致行为。

## Impact

- **S 端后端**（`server/app`）：新增注销相关 API（申请/撤销/状态查询/执行）；`users`、`device_grants`、`device_registry`、`codes` 模型需新增注销状态字段（alembic 迁移：本地生成 + MCP applyMigration）；订单/交易/退款表**只读不动**（留存）。
- **S 端前端**（`server/frontend`）：控制台新增账号安全/设置入口与注销向导弹层（后果告知 → 退款引导/放弃 → 密码确认 → 撤销期提示）；登录态为已申请注销的账号时展示撤销出口。
- **C 端**（`client/frontend` + `client/backend`）：认证失效统一处理——收到 401/失效响应时清空 config.json 中的 JWT 并导航回登录页。
- **测试**：S 端 pytest（全 mock）；S 端 e2e 全 mock 跑 PR CI；改交互类代码须本机先跑 C 端/S 端全量 e2e（本次以 S 端为主，C 端失效处理触达 client 端也需跑）。
- **法律文档**（docs/legal/）：协议 §三.4–7 注销条款组与隐私政策均已于 2026-08-29 更新到位；实施期仅核对（tasks 8.1–8.3）。

## Design Impact

- **受影响端**：S端（主）+ C端（登录失效处理，无新界面）。
- **受影响屏/弹层清单**：S端 控制台「账号安全」设置入口（新）、注销向导弹层（后果告知/退款引导/密码确认三步）、已申请注销账号的登录提示条（含撤销出口，warn 语气）；C端 复用既有登录屏（回跳目标，无像素变化）。
- **对象状态（对照 §5 状态语言总表）**：注销状态 pill——正常(默认不展示)、撤销期中(pill-status warn)、已注销(pill-tag)；提示条——后果确认 info、退款引导 info（带「去退款」出口）、放弃确认 warn、执行完成 ok、会话失效回登录页 err（补救句带出口）。
- **是否触碰共享段**：否。仅组合既有 .panel/.pill/.notice/.btn/.mcard 词汇，无新令牌/新组件。
- **是否需要原型先行**：否。S端 纯自有改动免原型（实现侧自查 + change 目录附截图对照）；C端 无界面变化，仅逻辑。
- **设计工件由谁产出**：实现侧自查对照（文案严格走 design-language §13：按钮全动词、无内部术语、补救句带可点击出口；语气词仅 info/ok/warn/err）。
