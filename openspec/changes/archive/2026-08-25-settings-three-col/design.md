# 设计：设定界面三段式 + 右侧 AI 栏

## 现状

- 写作视图：`.view.three-col` = col-tree（卷章树）/ col-middle（编辑区）/ col-ai（Rail：进度卡 + AI 写正文/续写/润色）
- 设定视图：`.view.two-col` = col-tree（8 项导航 + 进度条）/ col-panel（表单 + 确认完成）
- 「AI 帮我拆」四步向导嵌在主线表单（StoryArcForm）内部，与表单字段混排

## 目标布局

```
┌──────────┬────────────────────────────┬──────────────┐
│ 设定导航  │ 当前设定项表单               │ AI 栏         │
│ ·8项+进度 │ （主线：一句话/结局/分卷）    │ 主线时=四步向导│
│          │ 确认完成（panel-foot 不动）   │ 其他=说明/占位 │
└──────────┴────────────────────────────┴──────────────┘
```

与写作页同一个骨架（col-tree / col-middle / col-ai），同一个 236px 右栏宽，同一条左边框——一致性来自「长得一样、位置一样」。

## 多对象设定的内嵌子双栏（角色 / 伏笔）

一本小说有 N 个角色、N 条伏笔——这类「多对象」设定在中间栏内再分两层：

```
┌──────────┬───────────────┬─────────────────────┬──────────────┐
│ 设定导航  │ 内嵌左栏        │ 内嵌右侧             │ AI 栏         │
│          │ 角色列表        │ 选中角色的配置表单     │              │
│          │ ＋加角色        │ （字段编辑/删除）      │              │
└──────────┴───────────────┴─────────────────────┴──────────────┘
```

- 内嵌左栏宽度取窄定值（~180px），视觉层级弱于最左导航（字号更小、行高更紧），避免「两棵树打架」
- 现状对照：CharacterManager 目前是「列表 + 弹窗表单」，HooksSettingForm 是整块列表编辑——都改为「列表常驻左、表单常驻右」，弹窗退役
- 切换保护沿用现有口径：内嵌栏内切对象若有未保存修改，走同一个 confirm
- 单对象面板（题材/简介/主线/世界/风格/AI痕迹控制/AI模型）中间栏维持单表单
- 主线的「分卷规划」是行编辑表格不是多对象配置，不套这个模式

## 关键决策

1. **向导整体从 StoryArcForm 拆出**，成为独立组件挂到 SettingsView 的 col-ai
   - 拆出的组件持有自己的 step/input/running/audit 状态；卡片数据（arc）与自动保存仍走既有 API
   - 向导需要读当前卡内容（续步 next_step、AI 输入要带 arc）→ SettingsView 持有 arc 状态下发给两处（表单可编辑、向导可读）；落地方式：StoryArcForm 透出受控回调（onArcChange/arc），向导产出写回表单状态并自动保存
   - 表单与向导的联动通过状态提升实现，不改后端接口

2. **其他面板的右栏**：world/style/anti-ai 有字段级「AI 帮我填」（保留在字段行内，那是就地操作）；右栏放面板级说明卡。无 AI 面板放占位卡。右栏内容随 panel 切换。

3. **窄屏不照抄写作页**：写作页 <1024px 直接隐藏 col-ai（那边 AI 只是加速器）；设定页向导藏了就不可用 → 设定作用域下 col-ai 改为堆叠在主栏下方（grid 单列，col-ai border-left 改 border-top）。用 `.view.settings` 作用域类覆盖，不动写作页规则。

4. **main 容器**：two-col 的 col-panel 是 aside+main 两元素；three-col 需要 col-middle 包 col-panel（与写作页同构）。改动集中在 SettingsView 的 JSX 骨架与 book.css 少量新增。

## 风险与回归面

- StoryArcForm 拆向导是其最大一次结构改动：editedRef/P3-4 守护、自动保存、续步推断都要搬；vitest 7 用例中向导 5 用例改为渲染新组件（或经 SettingsView 集成测试）
- e2e story-arc.spec.ts：向导定位从表单内改到右栏（选择器加 `.col-ai` 作用域），3 用例需过一遍
- 设计稿 parity：设定屏不在 parity 清单内，无冲突

## 实现顺序（对应 tasks）

向导拆组件 → SettingsView 三栏骨架 + 右栏路由 → CSS（含窄屏堆叠）→ vitest/e2e 适配 → 全量回归。
