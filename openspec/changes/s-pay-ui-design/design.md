## Context

`docs/prd/s-payment-explore.md` 定稿了 S端 支付的全部业务口径（三档时长包、直充、按秒折算退款、订单独立台账、发票计税流），实现 change 等商户凭据。本 change 把界面层先做出来：S端 首次建立原型资产目录 `docs/design-s/prototypes/`，与 C端 机制平行但**无像素 parity 门禁**（cross-end 既定裁决：S端 证据=实现期截图对照，原型即设计事实源）。

## Goals / Non-Goals

**Goals**

- 3 个自包含原型 HTML：cashier（四态）、orders（列表+空态）、refund（折算预览+确认+终态），可双击直接评审
- 词汇零新增：全部用两端已同源的 .panel/.pill/.notice/.btn/.seg/.mcard/.field 族组合
- 文案对齐 §13：按钮全动词、补救句带出口、不出现内部术语（回调/订单状态机/异常单等），资金数字一律"¥xx.xx"
- 折算展示与秒级口径一致（探索纪要 §11 终版公式），给财务手册的例题提供界面对应

**Non-Goals**

- 不动 server/frontend 的 src/（实现 change 消费）
- 不做 C端 到期提示条（属 C端 批次）
- 不做管理面（ADMIN_TOKEN API 无 UI）
- 不建 baselines/parity 脚本（S端 无此层）

## Decisions

### D1 · 原型目录与登记机制

`docs/design-s/prototypes/`：`cashier.html` / `orders.html` / `refund.html` + `ADJUSTMENTS.md`（偏差登记簿，S端 首建）+ `README.md`（runbook：如何评审、实现期如何对照）。自包含 HTML——样式从 `server/frontend/src/design/base.css` 共享段原样内联（与 C端 原型同法），评审切换器放右上角并在 ADJUSTMENTS 登记为非基线元素（parity/截图时排除）。

### D2 · 收银台四态与状态语言映射

| 态 | 主元素 | 状态语言 |
| --- | --- | --- |
| 选套餐 | **双 seg 结构（2026-08-29 按竞品案例重排）**：档位 seg（PRO｜MAX·即将推出）→ 时长 seg（名+价格）→ 协议勾选（未勾选"同意并支付"禁用）→ 购买条（选中规格/设备数/应付 基准价划线+折扣价）→ 档位权益区；MAX=planned：切入显预告面板、时长区禁用。**促销位**：包年默认选中 +「最受欢迎」pill-accent + 近 30 天真实人数（<50 不展示） | 金额 pill-tag；推荐档 pill-accent |
| 等待支付 | 二维码占位 + 14:59 倒计时 + notice.info"请使用微信扫码" + 「我已支付但未到账」lnk 出口（触发查单的入口文案） | pill-status warn「等待支付」 |
| 支付成功 | notice.ok + 大号"已到货，待激活" + 主按钮「立即激活」+ 次链接"先存着，之后在「我的套餐」激活" | pill-status ok「已到货」 |
| 支付失败·下单失败 | notice.err"未产生扣款"+ 重试/返回重选/联系客服出口（拿二维码失败：网络/服务/配置错） | 无 |
| 支付失败·核对中 | notice.err"资金安全不会丢失，**请勿重复支付**"+ 联系客服/查看订单——**无重试按钮**（已收款被冻结态，重试=诱导重复支付） | 无 |
| 过期/失败 | notice.warn + 「重新下单」btn | pill-tag「已关闭」 |

### D3 · 订单列表与退款流

- orders.html：订单行 = 套餐名 + 实付金额 + 交易状态 pill（等待支付/已支付/退款族/核对中/已过期）——**纯交易口径**：权益状态（待激活/排队中/消耗中）与起止时间不进订单，只住"我的套餐"；退款入口仅已支付单可见；空态带"去购买"出口
- refund.html：核心是**折算预览**——"剩余 9 天 16 小时 48 分（按秒计），预计退 ¥9.70"，确认弹层(.mcard)列明 订单号/实付/剩余/退款额 四行 .num；终态：处理中（warn，"一般数分钟到 3 个工作日"）/ 已退款（ok）；拒绝态：err + 原因（不足 1 分/已到期/超 1 年窗口）+ 各自出口

### D4 · 文案禁令落地清单（§13 对照）

内部术语替换表：状态机→"订单进度"；异常单→"已冻结，请联系客服"（带 lnk）；回调/查单→不出现；"激活"一词在收银台全程不出现（直充口径）。金额全部两位小数 + ¥ 前缀，时长展示"X 天 Y 小时 Z 分"。

### D5 · 套餐对象与订单分离（评审补入，2026-08-28）

「套餐（权益）」与「订单（交易）」拆为两个对象/两屏：`membership.html`（「我的套餐」）承载权益视图——当前档位按**已激活行最高档归属**（激活包年即提升 5 台额度；2026-08-28 修订）、时长构成时间线（台账行：已耗完/消耗中/已激活·排队中，宽度按时长比例）、**待激活区块**（囤单：不计时/不占额度/全额退/立即激活按钮）、剩余合计（已激活口径）+ 待激活 N 个、设备额度与已绑定设备；`orders.html`（「我的订单」）回归纯交易记录，订单行去掉设备数等套餐属性。免费态展示试用倒计时与 1/1 设备额度。

### D6 · 控制台菜单 IA 与文案改名（2026-08-28 评审补入）

**常驻导航 5 项**：首页 · 我的套餐 · 我的订单 · 设备 · 我的账户。三条裁定：
1. **购买收银台是流程页，不占导航位**——入口=首页头部按钮/套餐卡/到期横幅，页内只留"‹ 返回控制台"（导航位留给"地点"，流程不占）
2. **激活码人工渠道整体丢弃（2026-08-28 拍板，先降级后丢弃）**：界面无任何兑换码入口，在线购买为唯一获得付费权益的通道；codes 表仅作内部权益台账（source=order）不可见；连带后果=商户号未获批时无人工出码兜底（Plan B 从"人工出码半自动"变为"暂缓上线"，风险已记入探索纪要）
3. **首页=汇总枢纽**：进行中事项横幅（L1 被动提醒：退款处理中/临期，登录即见）+ 四快捷卡（套餐/设备/下载客户端/账户），试用临期态强化转化（横幅+高亮套餐卡+「本地数据不受影响」红线文案）

**文案改名包（已批）**：我的 PRO→我的套餐、订单记录→我的订单、购买 PRO→购买套餐（**PRO 一词全面退役**：它只是早期免费/付费的区分叫法、不是品牌词——付费对象=套餐，功能表述用"套餐功能"，免费侧用"免费版"）、已关闭→已过期（超时）/已取消（用户主动）、已冻结→核对中（语气 err→warn：非不可逆）、取消并放弃本次订单→取消支付、折算→按剩余时长计算（政策文件保留"折算"）、设备额度→我的设备、账户→我的账户；「控制台」改名（如"个人中心"）牵动现网导航与 e2e，**单独立项不随本批**。

## Risks / Trade-offs

- [原型先行但实现未动，期间业务口径再变（折算又调）] → 原型内折算数字集中在每文件顶部的 mock 常量区，改口径只动一处；ADJUSTMENTS 登记
- [S端 首建原型目录，与 C端 机制并行产生认知成本] → README 首段写明差异（无 parity、无 baselines、截图对照即可）
- [评审切换器混入截图] → 已按 D1 登记为非基线元素

## Migration Plan

纯新增文档目录，无迁移。实现 change（s-wxpay-native）tasks 将引用这三个原型作为 Design Impact 的设计工件，验收=实现截图与原型对照入 change 目录。
