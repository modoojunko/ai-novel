核心变化
  • 大纲 + 细纲 合并入卷管理 — 卷纲在卷层级编辑，章纲在章层级编辑，不再是独立页面
  • 写作区 = 选择一章 → 写正文 — 不再是「prompts + write」两个功能页面
  • 左侧结构树固定存在 — 在所有 Tab 下都可见，随时知道自己在小说结构中的位置
  • Tab 数量不变（6→5） — 设定 / 卷管理 / 写作区 / 正文 / 线索

优点

  • Tab 名称直接对应小说结构，作家一看就懂
  • 不修改路由结构，不改 backend API
  • 结构树提供全局导航，解决了「我在哪一卷哪一章」的问题
  • 「卷纲」「章纲」回归它们的本质——是卷和章的属性，不是独立功能

缺点

  • 需要把 OutlinePage（当前大纲页）和 PromptsPage（当前细纲页）合并重构
  • 写作区需要整合章节选择逻辑
  • 需要处理向后兼容（已有数据的 phase 字段）
