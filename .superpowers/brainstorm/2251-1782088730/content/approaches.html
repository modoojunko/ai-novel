方案对比：三种改造思路

选一个方向，我再展开细节设计

A

最小改动

保留当前6个Tab标签，只做两件事：
1) 去掉 PhaseProgress 进度条（移除错误的「阶段」暗示）
2) 统一 backend phase 字段对应的 UI 标签为完整中文：
初始化→设定→大纲→细纲→写作→正文→线索
3) 侧边栏改为卷/章结构树
≈ 1-2 个文件改动，30 分钟

B

结构优先 (推荐)

重新组织导航标签，让结构可见：
设定 → 小说级元数据（世界/风格/角色/伏笔）
卷管理 → 卷列表 + 卷纲编辑 + 卷内章列表
写作区 → 选一章 → 写正文（合并当前prompts+write）
正文 → 已完成的章阅读器
线索 → 时间线/伏笔

在左侧新增一个始终可见的小说结构树（卷/章/状态）
≈ 4-5 个文件改动，2-3 小时

C

完全重构

抛弃Tab导航，改为双面板布局：
左侧面板 — 小说结构树（设定/卷/章/正文），始终可见
右侧主区 — 根据左侧选择动态切换内容
选择「设定」→展示设定页；选择「第1卷」→展示卷纲；选择「第3章」→展示章纲+正文

没有「阶段」概念，只有结构导航。章节状态作为小标签显示在树节点上。
≈ 8-10 个文件，全天后端配合，可能需要新的 API
